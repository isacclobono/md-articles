# Uber Redesigns M3DB Sharding with Subclusters to Limit Failure Impact

## Introduction

Running a time-series database at Uber's scale means ingesting millions of metrics per second across thousands of services. For years, M3DB served as our primary storage engine, deployed as a handful of massive, monolithic clusters. Each cluster spanned multiple availability zones and held a global hash ring encompassing every namespace we owned. The architecture worked—until it didn't.

A single bad deployment, a runaway query, or a network partition in one zone would cascade across the entire cluster. Because every node participated in the same global ring, a failure in the "payments" namespace could take down "rides" and "eats" metrics simultaneously. Our blast radius was effectively 100%. We needed a way to compartmentalize failure without sacrificing the operational simplicity of a single logical database.

The solution was subclusters: logically independent M3DB clusters, each owning a disjoint set of namespaces, coordinated by a lightweight metadata layer. This article breaks down why we made the change, how the architecture works under the hood, and the concrete operational improvements we've measured in production.

## Why This Matters

If you operate a multi-tenant time-series platform—whether it's observability, IoT telemetry, or financial tick data—you've likely felt the pain of shared-fate architectures. The symptoms are universal:

*   **Cascading outages**: A memory leak in one tenant's ingestion path OOMs nodes that also serve critical business metrics.
*   **Maintenance paralysis**: Rolling upgrades require draining the entire cluster, turning a 30-minute operation into a 6-hour coordinated dance across teams.
*   **Noisy neighbors**: A high-cardinality namespace from a new service evicts blocks from latency-sensitive dashboards because they share the same buffer pools and compaction queues.
*   **Capacity fragmentation**: You can't scale storage for "logging" independently from "metrics" because they're on the same nodes.

Subclusters solve this by introducing **failure domains aligned with business boundaries**. Each subcluster is a fully functional M3DB deployment with its own placement, its own etcd prefix, and its own lifecycle. The routing layer directs traffic based on namespace, so a failure in Subcluster A never touches Subcluster B. This isn't just theoretical—we've reduced our blast radius from 100% to roughly 15% (the size of our largest subcluster) and cut mean-time-to-recovery for zone-level incidents by 60%.

## How It Works

The core idea is straightforward: replace a single global hash ring with a **namespace-to-subcluster mapping** managed by a metadata service. Clients (or a sidecar proxy) consult this mapping to route writes and reads to the correct subcluster. Each subcluster runs a standard M3DB placement, completely unaware of the others.

**Request flow in detail:**

1.  **Client resolves namespace**: The client (or sidecar) extracts the namespace from the metric payload (e.g., `payments.latency`).
2.  **Routing lookup**: The routing layer consults its in-memory namespace map, populated from the Metadata Service via a long-poll watch on etcd.
3.  **Subcluster selection**: The map returns a subcluster identifier (e.g., `sc-payments`).
4.  **Placement lookup**: The client fetches the current M3DB placement for that subcluster (also from etcd, under a distinct prefix like `/m3db/placement/sc-payments`).
5.  **Direct write**: The client hashes the metric ID against *that subcluster's* ring and sends the write directly to the owning nodes. No proxy hop, no extra network hop.

**Failure isolation**: If Subcluster 2 (rides) suffers a network partition, the Metadata Service marks it unhealthy. The routing layer stops sending traffic to it. Subclusters 1 and 3 continue serving traffic uninterrupted. The rides team debugs their subcluster in isolation.

## Core Concepts

### Namespace as the Tenancy Unit
A *namespace* in M3DB corresponds to a retention policy and block size configuration (e.g., `metrics:10s:2h`, `metrics:1m:30d`). We treat each namespace as a tenant. The mapping from namespace → subcluster is static-ish—changed only during deliberate rebalancing—not on every request. This stability is critical for client-side caching.

### Subcluster Identity
Each subcluster gets a unique ID (`sc-uuid-v4`) and a human-readable alias (`sc-payments-prod`). It owns:
*   An etcd prefix for placement: `/m3db/placement/{subcluster-id}`
*   An etcd prefix for namespace metadata: `/m3db/namespace/{subcluster-id}`
*   A dedicated set of storage nodes (no sharing).
*   Its own compaction, replication, and repair loops.

### Metadata Service
A lightweight Go service (deployed as a DaemonSet for locality) that:
*   Watches etcd for subcluster health heartbeats.
*   Serves the namespace→subcluster map via a gRPC `WatchNamespaceMap` endpoint.
*   Exposes a `GetPlacement(subclusterID)` endpoint for clients to bootstrap.
*   Handles **split-brain prevention**: if a subcluster loses quorum, the metadata service stops advertising it until manual intervention.

### Client-Side Routing Library
We embed routing logic in `m3db-go-client` (and the equivalent Java/Python clients). The library:
*   Maintains a local LRU cache of namespace→subcluster mappings (TTL 30s, refreshed via watch).
*   Holds a placement per active subcluster.
*   Implements retry-with-backoff *scoped to the target subcluster*.
*   Emits structured logs with `subcluster_id` for distributed tracing.

## Examples & Code Walkthrough

Below is a simplified but production-shaped implementation of the routing client. It handles namespace resolution, placement caching, and subcluster-scoped retries.

```go
package m3router

import (
	"context"
	"errors"
	"sync"
	"time"

	"github.com/uber/m3db-go-client/m3db"
	"github.com/uber/m3db-go-client/m3db/client"
	"go.etcd.io/etcd/client/v3"
	"go.uber.org/zap"
)

// NamespaceMap maps a namespace string to a subcluster ID.
type NamespaceMap map[string]string

// SubclusterPlacement holds the current M3DB placement for a subcluster.
type SubclusterPlacement struct {
	ID        string
	Version   int64
	Ring      *m3db.Placement // M3DB's consistent hash ring
	UpdatedAt time.Time
}

// RoutingClient is the main entry point for namespace-aware writes/reads.
type RoutingClient struct {
	logger          *zap.Logger
	etcdCli         *clientv3.Client
	metadataPrefix  string // e.g., "/m3db/metadata"
	placementPrefix string // e.g., "/m3db/placement"

	// Guards the maps below.
	mu sync.RWMutex

	// namespaceMap: namespace -> subclusterID
	namespaceMap NamespaceMap

	// placements: subclusterID -> *SubclusterPlacement
	placements map[string]*SubclusterPlacement

	// m3dbClients: subclusterID -> m3db.Session (one per subcluster)
	m3dbClients map[string]client.Session

	// stopCh signals background watchers to exit.
	stopCh chan struct{}
}

// NewRoutingClient constructs a client and starts background watchers.
func NewRoutingClient(
	ctx context.Context,
	logger *zap.Logger,
	etcdEndpoints []string,
	metadataPrefix, placementPrefix string,
) (*RoutingClient, error) {
	etcdCli, err := clientv3.New(clientv3.Config{
		Endpoints:   etcdEndpoints,
		DialTimeout: 5 * time.Second,
	})
	if err != nil {
		return nil, err
	}

	rc := &RoutingClient{
		logger:          logger.Named("routing-client"),
		etcdCli:         etcdCli,
		metadataPrefix:  metadataPrefix,
		placementPrefix: placementPrefix,
		namespaceMap:    make(NamespaceMap),
		placements:      make(map[string]*SubclusterPlacement),
		m3dbClients:     make(map[string]client.Session),
		stopCh:          make(chan struct{}),
	}

	// Initial bootstrap (blocking)
	if err := rc.bootstrap(ctx); err != nil {
		etcdCli.Close()
		return nil, err
	}

	// Start long-poll watchers
	go rc.watchNamespaceMap(ctx)
	go rc.watchPlacements(ctx)

	return rc, nil
}

// bootstrap does a one-time full sync of namespace map and all placements.
func (rc *RoutingClient) bootstrap(ctx context.Context) error {
	// 1. Fetch namespace map
	resp, err := rc.etcdCli.Get(ctx, rc.metadataPrefix+"/namespaces", clientv3.WithPrefix())
	if err != nil {
		return err
	}
	for _, kv := range resp.Kvs {
		// key: /m3db/metadata/namespaces/payments.latency -> value: sc-payments-prod
		ns := extractNamespaceFromKey(string(kv.Key))
		rc.namespaceMap[ns] = string(kv.Value)
	}

	// 2. Fetch placements for each discovered subcluster
	subclusters := make(map[string]struct{})
	for _, sc := range rc.namespaceMap {
		subclusters[sc] = struct{}{}
	}
	for sc := range subclusters {
		if err := rc.syncPlacement(ctx, sc); err != nil {
			rc.logger.Warn("initial placement sync failed", zap.String("subcluster", sc), zap.Error(err))
			// Don't fail hard; watcher will retry.
		}
	}
	return nil
}

// watchNamespaceMap long-polls etcd for namespace map changes.
func (rc *RoutingClient) watchNamespaceMap(ctx context.Context) {
	watchCh := rc.etcdCli.Watch(ctx, rc.metadataPrefix+"/namespaces", clientv3.WithPrefix())
	for {
		select {
		case <-rc.stopCh:
			return
		case resp := <-watchCh:
			if resp.Err() != nil {
				rc.logger.Error("namespace map watch error", zap.Error(resp.Err()))
				continue
			}
			for _, ev := range resp.Events {
				ns := extractNamespaceFromKey(string(ev.Kv.Key))
				rc.mu.Lock()
				if ev.Type == clientv3.EventTypeDelete {
					delete(rc.namespaceMap, ns)
				} else {
					rc.namespaceMap[ns] = string(ev.Kv.Value)
				}
				rc.mu.Unlock()
			}
		}
	}
}

// watchPlacements watches placement changes for all known subclusters.
// In production we use a single watch on the placement prefix with a filter,
// but for clarity we show per-subcluster watches.
func (rc *RoutingClient) watchPlacements(ctx context.Context) {
	// This is a simplified loop; real implementation uses a single watch
	// and filters by subcluster ID in the key.
	ticker := time.NewTicker(10 * time.Second) // fallback periodic sync
	defer ticker.Stop()

	for {
		select {
		case <-rc.stopCh:
			return
		case <-ticker.C:
			rc.mu.RLock()
			subclusters := make([]string, 0, len(rc.placements))
			for sc := range rc.placements {
				subclusters = append(subclusters, sc)
			}
			rc.mu.RUnlock()

			for _, sc := range subclusters {
				if err := rc.syncPlacement(ctx, sc); err != nil {
					rc.logger.Warn("periodic placement sync failed", zap.String("subcluster", sc), zap.Error(err))
				}
			}
		}
	}
}

// syncPlacement fetches the latest placement for a subcluster and updates the M3DB session.
func (rc *RoutingClient) syncPlacement(ctx context.Context, subclusterID string) error {
	key := rc.placementPrefix + "/" + subclusterID
	resp, err := rc.etcdCli.Get(ctx, key)
	if err != nil {
		return err
	}
	if len(resp.Kvs) == 0 {
		return errors.New("placement not found")
	}

	placement, err := m3db.UnmarshalPlacement(resp.Kvs[0].Value)
	if err != nil {
		return err
	}

	rc.mu.Lock()
	defer rc.mu.Unlock()

	// Update placement cache
	rc.placements[subclusterID] = &SubclusterPlacement{
		ID:        subclusterID,
		Version:   placement.Version(),
		Ring:      placement,
		UpdatedAt: time.Now(),
	}

	// Create or update M3DB session for this subcluster
	if _, exists := rc.m3dbClients[subclusterID]; !exists {
		session, err := client.NewSession(client.Configuration{
			Placement: placement,
			// ... other config: timeouts, retries, etc.
		})
		if err != nil {
			return err
		}
		rc.m3dbClients[subclusterID] = session
	} else {
		// Hot-swap placement in existing session (M3DB client supports this)
		rc.m3dbClients[subclusterID].UpdatePlacement(placement)
	}
	return nil
}

// Write writes a metric to the correct subcluster based on namespace.
func (rc *RoutingClient) Write(ctx context.Context, namespace string, metric m3db.Metric) error {
	scID, ok := rc.resolveSubcluster(namespace)
	if !ok {
		return ErrNamespaceNotFound
	}

	session, ok := rc.getSession(scID)
	if !ok {
		return ErrSubclusterUnavailable
	}

	// Retry logic scoped to this subcluster's placement version.
	// We pass the placement version to detect stale routing.
	return session.WriteWithRetry(ctx, metric, client.WriteOptions{
		MaxRetries:      3,
		RetryDelay:      100 * time.Millisecond,
		PlacementVersion: rc.getPlacementVersion(scID),
	})
}

// resolveSubcluster is a fast, lock-free read (namespaceMap is only grown, rarely shrunk).
func (rc *RoutingClient) resolveSubcluster(namespace string) (string, bool) {
	rc.mu.RLock()
	defer rc.mu.RUnlock()
	sc, ok := rc.namespaceMap[namespace]
	return sc, ok
}

func (rc *RoutingClient) getSession(scID string) (client.Session, bool) {
	rc.mu.RLock()
	defer rc.mu.RUnlock()
	s, ok := rc.m3dbClients[scID]
	return s, ok
}

func (rc *RoutingClient) getPlacementVersion(scID string) int64 {
	rc.mu.RLock()
	defer rc.mu.RUnlock()
	if p, ok := rc.placements[scID]; ok {
		return p.Version
	}
	return 0
}

func (rc *RoutingClient) Close() error {
	close(rc.stopCh)
	rc.mu.Lock()
	defer rc.mu.Unlock()
	for _, s := range rc.m3dbClients {
		s.Close()
	}
	return rc.etcdCli.Close()
}

	ErrNamespaceNotFound     = errors.New("namespace not found in routing map")
	ErrSubclusterUnavailable = errors.New("subcluster session not available")
```
