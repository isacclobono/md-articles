# Petra Power has secured contracts worth nearly $9 million from the Department of Defense

## Introduction

When the DoD announced a $9 M award to Petra Power, the headlines focused on the dollar figure. For the engineering team, the real story is the set of non‑functional requirements that came attached: real‑time ingestion from the PROACT portal, NIST‑aligned RBAC, an immutable audit trail, and the ability to survive a surge of 10 k concurrent users across two U.S. regions. Those constraints forced us to re‑think the entire stack — from the API gateway down to the storage layer — and the result is a reference architecture we now reuse on every new defense‑tech engagement.

## Why This Matters

If you build software for regulated environments (defense, finance, healthcare) you already know that “just make it work” isn’t an option. The DoD contract bundle is a textbook case of **contract‑first, zero‑trust, observable microservices** that must pass a formal audit before a single line of code reaches production. The patterns we extracted — schema‑validated ingestion, hash‑chained audit logs, mTLS‑protected service mesh — are directly portable to any system that needs provable integrity and rapid scaling. Understanding them now saves you months of retrofitting later.

**Step‑by‑step walk‑through**

1. **Ingestion** – The adapter polls the SFTP drop zone and also exposes a REST endpoint for PROACT push notifications. Every payload is validated against a JSON Schema (AJV) before it ever touches Kafka.  
2. **Normalization** – A Spring Boot Streams job consumes `contract.raw`, maps the DoD‑specific fields to our canonical Avro model, enriches with classification tags (e.g., `CLIN`, `FAR clause`), and writes the result to PostgreSQL while emitting `contract.enriched`.  
3. **Entitlement** – The Go‑based RBAC service subscribes to `contract.enriched`, evaluates the requester’s roles against Casbin policies cached in Redis, and mints a short‑lived JWT (5 min TTL).  
4. **Billing** – The Python FastAPI engine reads the enriched contract, applies DoD pricing tables, creates an invoice row, generates a PDF via ReportLab, and posts the document to SAP through OData.  
5. **Audit** – Every state transition (ingest, normalize, authorize, bill) produces an event that the Pulsar‑backed audit service appends to a compacted topic. Each record carries a SHA‑256 hash of the previous record, forming a tamper‑evident chain. Quarterly we publish the Merkle root to a DoD‑approved WORM bucket.  
6. **Notification** – A .NET MassTransit consumer picks up success/failure events and delivers them over SIPRNet email and DoD Teams webhooks.  
7. **Observability** – All services export Prometheus metrics, OpenTelemetry traces, and structured JSON logs to Loki. Grafana dashboards give us SLA‑grade visibility (99.9 % latency < 200 ms for the ingestion path).

## Core Concepts

| Concept | Implementation Detail |
|---------|-----------------------|
| **Contract‑first APIs** | OpenAPI 3.1 documents live in `docs/contracts/`; CI runs `spectral lint` and generates server stubs for every language. |
| **Schema validation at the edge** | AJV compiles the JSON Schema once at startup; validation is a pure function, no I/O, so the hot path stays < 1 ms. |
| **Event‑driven normalization** | Kafka Streams provides exactly‑once semantics; Avro schemas are registered in Confluent Schema Registry with backward compatibility enforced. |
| **Policy as code** | Casbin models (RBAC + ABAC) are stored in Git, versioned, and loaded at container start. Redis caches the compiled policy for sub‑millisecond decisions. |
| **Immutable audit log** | Pulsar’s compacted topics guarantee the latest state per key; RocksDB backs the local segment for fast hash‑chain verification. |
| **Zero‑trust networking** | Istio injects sidecars automatically; `PeerAuthentication` enforces `STRICT` mTLS. All egress passes through an egress gateway with mutual TLS to the DoD SIPRNet. |
| **Secrets lifecycle** | Vault dynamic database credentials rotate every 4 h; JWT signing keys are generated by Vault’s transit engine and never leave the HSM. |
| **Multi‑region active‑active** | Kafka MirrorMaker 2 replicates topics across US‑East and US‑West; PostgreSQL uses synchronous streaming replication with `pg_failover_slots`. |

## Examples & Code Walkthrough

### 7.1 Contract Ingestion Adapter (Node.js / Fastify)

```javascript
// ingestionAdapter.js
// ------------------------------------------------------------
// Pulls contract payloads from DoD SFTP/REST, validates them
// against a JSON Schema, and publishes the raw event to Kafka.
// ------------------------------------------------------------

import Fastify from 'fastify';
import { Kafka } from 'kafkajs';
import { readFileSync } from 'fs';
import { fileURLToPath } from 'url';
import { dirname, join } from 'path';
import Ajv from 'ajv';
import addFormats from 'ajv-formats';

// ---- Configuration -------------------------------------------------
const KAFKA_BOOTSTRAP = process.env.KAFKA_BOOTSTRAP ?? 'kafka:9092';
const TOPIC_RAW = 'contract.raw';
const SCHEMA_PATH = join(dirname(fileURLToPath(import.meta.url)), 'schemas', 'contract.v1.json');

// ---- Fastify & Kafka bootstrap ------------------------------------
const fastify = Fastify({ logger: true });
const kafka = new Kafka({ clientId: 'petra-ingest', brokers: [KAFKA_BOOTSTRAP] });
const producer = kafka.producer({ allowAutoTopicCreation: false });

// ---- JSON Schema validation ----------------------------------------
const ajv = new Ajv({ allErrors: true, strict: false });
addFormats(ajv);
const rawSchema = JSON.parse(readFileSync(SCHEMA_PATH, 'utf8'));
const validateContract = ajv.compile(rawSchema);

// ---- Graceful shutdown ---------------------------------------------
async function shutdown(signal) {
  fastify.log.info({ signal }, 'Shutting down...');
  await producer.disconnect();
  await fastify.close();
  process.exit(0);
}
['SIGINT', 'SIGTERM'].forEach(sig => process.on(sig, () => shutdown(sig)));

// ---- Route: POST /contracts ----------------------------------------
fastify.post('/contracts', {
  schema: {
    body: rawSchema,               // Fastify will also validate, but we keep AJV for custom error payloads
    response: {
      202: { type: 'object', properties: { messageId: { type: 'string' } } },
      400: { type: 'object', properties: { errors: { type: 'array' } } }
    }
  }
}, async (request, reply) => {
  const payload = request.body;

  // Defensive: AJV gives us a detailed error array we can forward to the caller
  if (!validateContract(payload)) {
    const errors = validateContract.errors?.map(e => ({
      keyword: e.keyword,
      instancePath: e.instancePath,
      message: e.message,
      params: e.params
    })) ?? [];

    fastify.log.warn({ errors }, 'Contract validation failed');
    return reply.code(400).send({ errors });
  }

  // Produce to Kafka – we use the contract number as key for partitioning
  const key = payload.contractNumber ?? crypto.randomUUID();
  try {
    const result = await producer.send({
      topic: TOPIC_RAW,
      messages: [{ key, value: JSON.stringify(payload), headers: { source: 'ingest-adapter' } }],
      acks: -1,                     // wait for all in‑sync replicas
      timeout: 5000
    });

    fastify.log.info({ key, partition: result[0].partition }, 'Published raw contract');
    return reply.code(202).send({ messageId: result[0].baseOffset.toString() });
  } catch (err) {
    fastify.log.error({ err, key }, 'Kafka produce failed');
    return reply.code(502).send({ errors: [{ message: 'Unable to queue contract for processing' }] });
  }
});

// ---- Start ---------------------------------------------------------
async function start() {
  await producer.connect();
  await fastify.listen({ port: 8080, host: '0.0.0.0' });
  fastify.log.info('Ingestion adapter listening on :8080');
}

start().catch(err => {
  fastify.log.fatal({ err }, 'Failed to start ingestion adapter');
  process.exit(1);
});
```

**What the snippet demonstrates**

* **Fail‑fast validation** – AJV runs once at startup; the hot path only calls the compiled function.  
* **Explicit error payloads** – The caller receives a structured list of schema violations, which the DoD integration team can feed back into their CI pipeline.  
* **Idempotent key selection** – Using `contractNumber` guarantees ordering per contract; a UUID fallback prevents hot partitions when the field is missing.  
* **Producer hardening** – `acks: -1` and a 5 s timeout give us the durability guarantees the audit clause demands.  
* **Graceful shutdown** – The signal handler drains the producer before the process exits, avoiding lost messages during rolling deploys.

### 7.2 Normalization Service (Java / Spring Boot – Kafka Streams)

```java
// NormalizationStream.java
package com.petra.contract.normalization;

import org.apache.kafka.common.serialization.Serdes;
import org.apache.kafka.streams.*;
import org.apache.kafka.streams.kstream.*;
import org.apache.kafka.streams.state.StoreBuilder;
import org.apache.kafka.streams.state.Stores;
import io.confluent.kafka.streams.serdes.avro.SpecificAvroSerde;
import com.petra.avro.ContractRaw;
import com.petra.avro.ContractEnriched;

import java.util.Properties;

public class NormalizationStream {

    public static void main(String[] args) {
        Properties props = new Properties();
        props.put(StreamsConfig.APPLICATION_ID_CONFIG, "contract-normalizer");
        props.put(StreamsConfig.BOOTSTRAP_SERVERS_CONFIG, System.getenv("KAFKA_BOOTSTRAP"));
        props.put(StreamsConfig.DEFAULT_KEY_SERDE_CLASS_CONFIG, Serdes.String().getClass());
        props.put(StreamsConfig.DEFAULT_VALUE_SERDE_CLASS_CONFIG, SpecificAvroSerde.class);
        props.put("schema.registry.url", System.getenv("SCHEMA_REGISTRY"));
        props.put(StreamsConfig.PROCESSING_GUARANTEE_CONFIG, StreamsConfig.EXACTLY_ONCE_V2);

        StreamsBuilder builder = new StreamsBuilder();

        // ---- State store for classification lookup (e.g., CLIN -> description) ----
        StoreBuilder<?> clinStore = Stores.keyValueStoreBuilder(
                Stores.persistentKeyValueStore("clin-lookup"),
                Serdes.String(),
                Serdes.String()
        );
        builder.addStateStore(clinStore);

        KStream<String, ContractRaw> raw = builder.stream("contract.raw",
                Consumed.with(Serdes.String(), specificAvroSerde(ContractRaw.class)));

        KStream<String, ContractEnriched> enriched = raw
                .filter((k, v) -> v != null)                     // drop tombstones
                .transformValues(() -> new EnrichmentTransformer(), "clin-lookup")
                .mapValues(this::toEnriched);

        enriched.to("contract.enriched",
                Produced.with(Serdes.String(), specificAvroSerde(ContractEnriched.class)));

        KafkaStreams streams = new KafkaStreams(builder.build(), props);
        streams.start();
        Runtime.getRuntime().addShutdownHook(new Thread(streams::close));
    }

    private ContractEnriched toEnriched(ContractRaw raw) {
        // Mapping logic – omitted for brevity; uses Avro builders for type safety
        return ContractEnriched.newBuilder()
                .setContractNumber(raw.getContractNumber())
                .setAgency(raw.getAgency())
                .setValue(raw.getValue())
                .setClassificationTags(raw.getClassificationTags())
                .build();
    }

    private <T> SpecificAvroSerde<T> specificAvroSerde(Class<T> clazz) {
        SpecificAvroSerde<T> serde = new SpecificAvroSerde<>();
        serde.configure(java.util.Collections.singletonMap("schema.registry.url",
                System.getenv("SCHEMA_REGISTRY")), false);
        return serde;
    }
}
```

**Key take‑aways**

* **Exactly‑once v2** – Guarantees no duplicate enrichment even under broker failover.  
* **Stateful enrichment** – The `clin-lookup` store is populated by a separate CDC job that streams the DoD CLIN reference table into Kafka; the transformer reads it locally, avoiding a remote call per record.  
* **Avro + Schema Registry** – Schema evolution is enforced at compile time; any breaking change fails the CI pipeline before deployment.

## Best Practices

1. **Validate at the edge, trust inside** – Once a message passes the AJV gate, downstream services can assume structural correctness and focus on business logic.  
2. **Keep the contract schema in version control** – Treat the JSON/Avro definitions as source code; run `spectral lint` and `avro-maven-plugin` in every PR.  
3. **Use short‑lived JWTs with asymmetric keys** – The RBAC service signs with an RS256 key stored only in Vault; verification keys are public and can be cached by API gateways.  
4. **Hash‑chain every audit record** – The SHA‑256 of the previous record becomes a field in the next; verification is a single linear scan, cheap enough for quarterly Merkle‑root generation.
