# GitHub Trending: elayadesign/ai-design-skills

## Introduction
The repository elayadesign/ai-design-skills surfaced on GitHub Trending under the Artificial Intelligence category, drawing attention for its approach to programmatically evaluating and cultivating design competencies through machine learning. Rather than treating design as an entirely subjective craft, the project introduces a reproducible pipeline for assessing visual design skills against learnable criteria, generating actionable feedback, and supporting automated design education workflows. In our team's experience reviewing design-centric AI tools, the distinguishing factor here is the grounding of evaluation logic in concrete visual features rather than opaque generative hype.

## Why This Matters
Software engineers and engineering managers often encounter design skill gaps when onboarding new team members or aligning cross-functional product teams. Manual code reviews of UI/UX implementations consume disproportionate cycles, and subjective feedback loops slow iteration. This project addresses a concrete production pain point: the need for scalable, data-driven design skill assessment that integrates into existing CI/CD and review tooling. By extracting measurable design attributes from Figma files, Sketch exports, or rendered UI screenshots, the repository enables automated triaging of design PRs, prioritization of accessibility fixes, and structured mentorship pathways. We've seen similar patterns fail when teams attempt pure text-based prompting without visual grounding; this repo's architecture avoids that pitfall by tethering every evaluation step to pixel-level or vector-level evidence.

## How It Works
The core mechanism revolves around a three-stage pipeline: input normalization, visual feature extraction, and skill-mapping inference. Each stage is deliberately decoupled so that model upgrades or criterion revisions require minimal downstream changes.

**Stage 1 – Normalize & Preprocess:**  
The pipeline accepts heterogeneous design artifacts. Figma JSON payloads are parsed to extract component hierarchies, constraints, and typography tokens. Raster inputs (PNG, JPEG) run through a lightweight resize-and-normalize step, keeping aspect ratios intact while downsampling to 512×512 pixels to bound compute. SVG inputs are converted to path data and rasterized at a consistent DPI. Error handling validates MIME types, schema version compatibility, and maximum file size (enforced at 10MB per asset in the default configuration). Invalid inputs raise `ValueError` with descriptive codes, halting downstream processing.

**Stage 2 – Extract Visual Features:**  
A frozen CLIP ViT-L/14 encoder runs on the preprocessed asset, producing a 768-dimensional embedding per image patch. These embeddings are aggregated via attention pooling to form a single global representation. The model weights are pinned to `openai/clip-vit-large-patch14` at `sha: 368f3e4` to ensure reproducibility across inference runs. For vector assets, we additionally compute path-level metrics: bounding box ratios, color histogram divergence from a base "neutral" palette, and node density per 100px². These supplementary features are concatenated to the CLIP embedding, yielding a 896-dimensional feature vector per asset.

**Stage 3 – Map Features to Skill Criteria:**  
A lightweight multilayer perceptron (MLP) with two hidden layers (256 and 128 units, ReLU activation, dropout 0.1) maps the feature vector to a 20-dimensional logits space. Each dimension corresponds to a defined design skill: contrast_ratio, typographic_hierarchy, spacing_consistency, accessibility_color_contrast, visual_weight_balance, and others. Logits are passed through a sigmoid function to produce per-skill scores in [0, 1]. A calibrated threshold (default 0.65) marks a skill as "proficient"; scores below trigger auto-generated feedback snippets drawn from a curated library of remediation hints. The MLP weights are trained on a labeled dataset of 12,000 Figma files independently assessed by senior designers, with inter-rater agreement (Cohen's kappa) of 0.78 reported in the repo's documentation.

**Stage 4 – Generate Structured Report:**  
The final output is a JSON object conforming to the `design-skill-v1` schema. Fields include `asset_id`, `overall_score`, `skill_breakdown` (map of skill name to {score, status, feedback}), `generated_at` timestamp, and `model_version`. This schema is deliberately versioned; downstream consumers can pin to specific versions without schema drift. The report is written to a local `.json` file by default, but the pipeline supports posting to GitHub Checks API, Slack webhooks, or an internal design review dashboard via a pluggable `Reporter` interface.

## Core Concepts
- **Visual Feature Grounding:** Every skill evaluation traces back to concrete pixel or vector attributes. This prevents the "black box" problem common in generative AI tools and enables targeted debugging when scores drift.
- **Schema Versioning:** The `design-skill-v1` JSON schema is immutable after release. New skills or revised scoring rubrics land as `design-skill-v2`, `v3`, etc., with explicit migration scripts.
- **Modality Agnosticism:** The pipeline equally handles raster images, SVG path data, and Figma JSON, making it usable across design toolchains without custom adapters for each.
- **Deterministic Inference:** By freezing both the CLIP encoder and MLP weights, running the same asset through the pipeline on different machines produces byte-identical outputs, facilitating reproducible audits.
- **Feedback Library Decoupling:** Remediation hints live in a separate `feedback_catalog.json` file, editable by non-technical domain experts without touching Python code.

# design_skill_assessor.py
"""
Pipeline for evaluating design competencies from visual assets.
Supports Figma JSON, SVG, and raster image inputs.
Outputs a design-skill-v1 conformant JSON report.
"""

import json
import os
from dataclasses import dataclass, asdict
from enum import Enum
from pathlib import Path
from typing import Dict, List, Optional, Tuple

import numpy as np
from PIL import Image
import torch
from transformers import CLIPModel, CLIPProcessor


class InputType(Enum):
    FIGMA_JSON = "figma_json"
    SVG = "svg"
    RASTER = "raster"


@dataclass
class SkillResult:
    name: str
    score: float  # range [0, 1]
    status: str   # "proficient" if score >= 0.65 else "developing"
    feedback: str  # auto-generated remediation hint


@dataclass
class DesignReport:
    asset_id: str
    overall_score: float
    skill_breakdown: Dict[str, SkillResult]
    generated_at: str
    model_version: str


# Bounded thresholds for skill classification
PROFICIENCY_THRESHOLD = 0.65

# Supported skill names; order must match MLP output dimensions
SKILL_NAMES = [
    "contrast_ratio",
    "typographic_hierarchy",
    "spacing_consistency",
    "accessibility_color_contrast",
    "visual_weight_balance",
    "alignment_precision",
    "grid_adherence",
    "information_hierarchy",
    "negative_space_usage",
    "color_harmony",
]


class DesignSkillAssessor:
    """Core assessor that normalizes input, extracts features, and maps to skill scores."""

    def __init__(
        self,
        model_name: str = "openai/clip-vit-large-patch14",
        mlp_checkpoint: Optional[str] = None,
        device: Optional[str] = None,
    ):
        self.device = device or ("cuda" if torch.cuda.is_available() else "cpu")
        self.model = CLIPModel.from_pretrained(model_name).to(self.device)
        self.processor = CLIPProcessor.from_pretrained(model_name)
        self.model.eval()  # deterministic inference

        # Initialize MLP head for skill mapping
        self.mlp = torch.nn.Sequential(
            torch.nn.Linear(768, 256),
            torch.nn.ReLU(inplace=True),
            torch.nn.Dropout(p=0.1),
            torch.nn.Linear(256, 128),
            torch.nn.ReLU(inplace=True),
            torch.nn.Dropout(p=0.1),
            torch.nn.Linear(128, len(SKILL_NAMES)),
        )

        if mlp_checkpoint and os.path.isfile(mlp_checkpoint):
            state = torch.load(mlp_checkpoint, map_location=self.device)
            self.mlp.load_state_dict(state)
            self.mlp.to(self.device)
            self.mlp.eval()
        else:
            # If no checkpoint provided, weights remain randomly initialized;
            # in production this would be replaced with trained weights.
            pass

    def _classify_input(self, filepath: Path) -> Tuple[InputType, Optional[dict]]:
        """Determine input type and parse structured data if applicable."""
        ext = filepath.suffix.lower()
        if ext in {".png", ".jpg", ".jpeg", ".webp"}:
            return InputType.RASTER, None
        if ext == ".svg":
            return InputType.SVG, None
        if ext in {".json"} and filepath.name.startswith("figma_"):
            with open(filepath, "r") as f:
                data = json.load(f)
            return InputType.FIGMA_JSON, data
        # Fallback: attempt MIME-based detection
        raise ValueError(f"Unsupported file type or unrecognized Figma JSON: {filepath}")

    def _normalize_raster(self, filepath: Path) -> Image.Image:
        """Load, resize, and normalize a raster image for CLIP encoding."""
        img = Image.open(filepath).convert("RGB")
        # Resize maintaining aspect ratio, max 512px on long side
        ratio = min(512 / img.width, 512 / img.height)
        new_size = (max(1, int(img.width * ratio)), max(1, int(img.height * ratio)))
        img = img.resize(new_size, Image.LANCZOS)
        # Pad to 512×512 with white background (CLIP expects consistent input size)
        padded = Image.new("RGB", (512, 512), (255, 255, 255))
        padded.paste(img, ((512 - new_size[0]) // 2, (512 - new_size[1]) // 2))
        return padded

    def _extract_embedding(self, image: Image.Image) -> np.ndarray:
        """Run CLIP encoder and return the aggregated global embedding."""
        inputs = self.processor(images=image, return_tensors="pt").to(self.device)
        with torch.no_grad():
            image_features = self.model.get_image_features(**inputs)
        # Normalize to unit vector
        embedding = image_features / torch.norm(image_features, dim=-1, keepdim=True)
        return embedding.cpu().numpy()[0]
