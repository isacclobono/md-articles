# How to Build an AI Call Agent with Python: STT, Groq LLM and TTS

## Introduction
A few years ago, we were asked to replace a manual support line with an autonomous voice assistant. The goal was simple: listen, understand, reply, and hang up—all within a single conversation. The trick was that users would hang up mid‑sentence, or they would notice a half‑second pause that made the bot feel robotic. After a few false starts, we realized the problem wasn’t just “pick a model.” It was about orchestrating three very different services—speech‑to‑text, large‑language inference, and text‑to‑speech—into a single, latency‑conscious pipeline that could survive network jitter, partial transcripts, and sudden interruptions.

## Why This Matters
Most developers treat each component as a separate microservice, ignoring the “uncanny valley of latency.” Humans start feeling “off” when end‑to‑end delay exceeds ~300 ms, and anything above 600 ms feels broken. The hidden cost isn’t CPU; it’s the physical travel time of photons across data‑center hops, ISP backbones, and the carrier network. Deterministic inference becomes a competitive advantage when you can guarantee sub‑500 ms turnaround on a best‑effort internet connection.

Choosing Groq over a generic GPU cluster is a direct response to that need. Groq’s LPU (Language Processing Unit) offers single‑digit millisecond inference with zero queue jitter, while a GPU can vary by tens of milliseconds depending on concurrent jobs. In a voice‑first product, that variance translates to noticeable lag or garbled speech.

## How It Works
The system is built as a **dual‑track, event‑driven pipeline**. Track A handles inbound audio (microphone → telephony → STT), Track B handles outbound audio (LLM → TTS → telephony). A central orchestrator, `VoiceAgentCore`, stitches the two tracks together, manages barge‑in, and applies backpressure via async queues.

```mermaid
flowchart TD
    A[Telephony (SIP/RTP)] --> B[Media Server]
    B --> C[Streaming STT (Deepgram WebSocket)]
    C --> D[Partial Transcript Queue]
    D --> E[VoiceAgentCore]
    E --> F[Groq LLM (Tool Calls)]
    F --> G[TTS Stream (ElevenLabs WebSocket)]
    G --> H[Media Server]
    H --> I[PSTN / User]
    J[User Audio] --> B
    K[Kill Switch / Barge‑In] --> E
    E --> L[State Machine: IDLE/LISTENING/THINKING/SPEAKING]
```

**Key concepts in the diagram**

1. **Streaming STT** – Deepgram (or AssemblyAI) sends incremental transcripts as soon as they’re ready, not waiting for a full utterance. This lets the LLM start processing before the user has finished speaking.
2. **Partial Transcript Queue** – An `asyncio.Queue` holds chunks of text. The `TokenAccumulator` buffers them until a semantic boundary (sentence, question mark, etc.) is reached, then flushes to the TTS track.
3. **Kill Switch** – A low‑latency flag generated by server‑side VAD (Silero) or by detecting a sudden drop in audio level. When set, the orchestrator transitions to `INTERRUPTED`, cancels any ongoing TTS, and rewinds the audio buffer to capture the new utterance.
4. **Deterministic Groq** – The LLM stream is consumed token‑by‑token. A custom parser strips special tokens and forwards clean text to the TTS queue, keeping the pipeline tight.

The rest of the article digs into each piece, showing how we turned the theory into production‑grade Python code.

## Core Concepts
- **State Machine** – `IDLE → LISTENING → THINKING → SPEAKING → INTERRUPTED`. Each state defines allowed transitions and cleanup actions (e.g., cancel TTS stream, flush STT buffer).
- **Concurrency Model** – `asyncio` is the glue. Two producer‑consumer pairs (`stt_queue`, `tts_queue`) operate independently, while a single consumer (`llm_task`) processes tokens.
- **TokenAccumulator** – Prevents the “choppy prosody” problem that appears when you feed three‑word bursts to a TTS engine. It respects a max‑char limit and a boundary regex.
- **Resampling** – Audio formats differ everywhere (Twilio μ‑law @8 kHz, Deepgram @16 kHz, ElevenLabs @24 kHz). A background thread pool runs `soxr` or `librosa` to keep the pipeline format‑agnostic.
- **Observability** – OpenTelemetry spans per stage (`twilio.receive`, `stt.partial`, `llm.first_token`, `tts.first_chunk`). P99 latency > 800 ms triggers an alert.

### TokenAccumulator
```python
# core/token_accumulator.py
import asyncio
import re
from typing import AsyncGenerator, List

class TokenAccumulator:
    """
    Buffers LLM tokens until a semantic boundary is hit.
    This reduces the number of TTS API calls and preserves natural prosody.
    """
    def __init__(
        self,
        max_chars: int = 120,
        boundary_pattern: str = r'[.?!]\s+',
    ):
        self.buffer: List[str] = []
        self.max_chars = max_chars
        self.boundary_re = re.compile(boundary_pattern)
        self._flush_event = asyncio.Event()
        self._current = ""

    async def feed(self, token: str) -> None:
        """
        Append a token and signal that a flush may be needed.
        """
        self._current += token
        self.buffer.append(token)
        self._flush_event.set()

    async def flush_if_ready(self) -> AsyncGenerator[str, None]:
        """
        Yield accumulated text when a boundary is found or max_chars exceeded.
        If nothing to flush, yields nothing.
        """
        await self._flush_event.wait()
        self._flush_event.clear()

        if not self._current:
            return

        # Check for semantic boundary
        if self.boundary_re.search(self._current):
            text = self._current
            self._current = ""
            yield text
            return

        # Check length limit
        if len(self._current) >= self.max_chars:
            # Try to cut at the last space to avoid splitting words
            cut = self._current.rfind(" ")
            if cut != -1:
                text = self._current[:cut]
                self._current = self._current[cut+1:]
                yield text
            else:
                yield self._current
                self._current = ""
            return

        # No flush condition met yet
        return
```

### VoiceAgentCore Orchestrator
```python
# core/voice_agent.py
import asyncio
import logging
from enum import Enum, auto
from typing import Optional

from core.token_accumulator import TokenAccumulator

logger = logging.getLogger(__name__)

class State(Enum):
    IDLE = auto()
    LISTENING = auto()
    THINKING = auto()
    SPEAKING = auto()
    INTERRUPTED = auto()

class VoiceAgentCore:
    """
    Central orchestrator for the STT → Groq → TTS pipeline.
    Manages state, async queues, and barge‑in handling.
    """
    def __init__(self, stt_queue: asyncio.Queue, tts_queue: asyncio.Queue):
        self.stt_queue = stt_queue
        self.tts_queue = tts_queue
        self.state = State.IDLE
        self.accumulator = TokenAccumulator()
        self.barge_in_flag = asyncio.Event()
        self._llm_task: Optional[asyncio.Task] = None
        self._tts_task: Optional[asyncio.Task] = None

    async def transition(self, target: State) -> None:
        """Log state changes for observability."""
        logger.debug("State transition %s → %s", self.state, target)
        self.state = target

    async def start_listening(self) -> None:
        """Move to LISTENING and wait for STT output."""
        await self.transition(State.LISTENING)
        # The STT producer will fill self.stt_queue; we consume in _process_stt
        # This method just signals readiness.
        logger.debug("Agent ready to capture speech.")

    async def handle_stt_chunk(self, transcript: str) -> None:
        """
        Called from the STT consumer. Feed transcript into the accumulator
        and, if a boundary is reached, dispatch to the LLM.
        """
        if self.state == State.INTERRUPTED:
            # Discard any pending text; user is speaking again.
            self.accumulator = TokenAccumulator()
            await self.transition(State.LISTENING)
            return

        await self.accumulator.feed(transcript)

        # Try to flush if we have a complete thought
        async for chunk in self.accumulator.flush_if_ready():
            await self.tts_queue.put(chunk)
            await self.transition(State.THINKING)
            # Kick off LLM processing in background
            self._llm_task = asyncio.create_task(self._run_llm(chunk))

    async def _run_llm(self, prompt: str) -> None:
        """
        Deterministic Groq inference.
        This is a placeholder for actual client usage (groq_client.chat.completions.create).
        """
        logger.debug("Sending prompt to Groq: %s", prompt[:60])
        # Simulate streaming tokens
        tokens = prompt.split()
        for token in tokens:
            # In real code, await groq_client.chat.completions.create(...)
            await asyncio.sleep(0.001)  # placeholder latency
            await self.accumulator.feed(token)

        # After the LLM finishes, we assume the accumulated tokens are ready for TTS
        # The accumulator will be flushed by the next STT chunk or a timeout.
        await self.transition(State.SPEAKING)

    async def handle_barge_in(self) -> None:
        """
        Triggered by VAD or sudden audio level drop.
        Cancels any ongoing TTS, rewinds to LISTENING.
        """
        self.barge_in_flag.set()
        if self._tts_task and not self._tts_task.done():
            self._tts_task.cancel()
        await self.transition(State.INTERRUPTED)
        logger.debug("Barge‑in detected, returning to LISTENING.")
```

## Best Practices
- **Never block the event loop on I/O** – offload resampling, VAD, or heavy CPU work to a `ThreadPoolExecutor`.
- **Circuit‑breaker for Groq** – wrap the Groq client in a `circuitbreaker.CircuitBreaker` and fall back to a local `llama.cpp` instance when the provider returns 5xx.
- **Structured logging** – include trace IDs, stage latencies, and state transitions. Use `structlog` or the OpenTelemetry Python SDK.
- **Health‑check endpoints** – expose `/healthz` (overall status), `/metrics` (Prometheus style), and `/ready` (dependencies like Deepgram key, Groq token).
- **Secret management** – store API keys in environment variables or a secret manager; rotate them regularly.

## Common Mistakes & Anti-Patterns
1. **Blocking the event loop with audio decoding** – Using `pydub` or `soxr` directly in `async def` stalls the whole pipeline. Fix: run those calls via `loop.run_in_executor`.
2. **Sending tiny TTS chunks** – Feeding the TTS engine one‑word bursts kills prosody and incurs massive API cost. Fix: implement a buffer like `TokenAccumulator` with a max‑char limit and boundary detection.
3. **Ignoring VAD on the server side** – Relying only on STT endpointing leads to “dead air” where the assistant speaks after the user has already finished. Fix: add Silero VAD and propagate a `barge_in_flag` to the orchestrator.
4. **Hard‑coding sample rates** – Assuming Twilio’s μ‑law is the only format leads to resampling errors. Fix: normalize all audio to a common rate (e.g., 48 kHz) early in the pipeline.
