# Cheap bloom for a Canvas 2D game in 8 lines (no WebGL)

## Introduction

I've shipped three commercial HTML5 games. Two of them died in QA because "the glow effect tanks FPS on my mom's laptop."

The third one runs at 60fps on a 2015 MacBook Air with Intel HD 6000 graphics. The difference wasn't a better algorithm—it was respecting how the browser compositor actually works.

Every Canvas 2D tutorial shows you `ctx.filter = 'blur(20px)'` and calls it a day. What they don't show is the DevTools Performance tab lighting up like a Christmas tree: *Layer invalidation. Texture re-upload. Main thread stall.* The browser's `filter` implementation is fast—in C++, on the GPU. But toggling it on the *primary* context every frame forces the compositor to tear down and rebuild the layer tree.

Bloom is just a separable convolution. The browser already has a hardware-accelerated separable convolution. The trick isn't writing a shader. The trick is structuring your render pipeline so the compositor never sees a state change on the visible canvas.

## Why This Matters

If you're building a web game, you're not fighting the math. You're fighting the **frame budget**.

At 60fps, you have 16.67ms. At 120fps (increasingly common on mobile), you have 8.33ms. A naive bloom implementation—draw scene, blur, draw scene again—eats 4–6ms on integrated graphics just in driver overhead and texture shuffling. That's your physics budget. Your AI budget. Your networking budget.

I've seen teams rewrite their renderer in WebGL *solely* because they couldn't get bloom performant in Canvas 2D. That's a month of engineering time, a larger bundle, loss of accessibility tree, and a debugging nightmare—all because they were holding the 2D API wrong.

This approach keeps you in Canvas 2D. It keeps your hit-testing, your text rendering, your DevTools inspection. It costs one persistent `OffscreenCanvas` (or a hidden `<canvas>`), eight lines in your render loop, and zero external dependencies.

## How It Works

The core insight: **separate the emissive layer from the composite layer.**

Instead of blurring the *entire frame* on the main context (which invalidates the compositor's cached texture), we draw *only glowing objects* to a persistent offscreen buffer. We blur *that* buffer in place. Then we composite the result additively onto the main canvas *once*, with zero filter state changes on the primary context.

The main context stays clean. `source-over` all day. The compositor sees a static texture upload—exactly what it's optimized for.

**Step-by-step:**

1. **Init (once):** Create a detached `OffscreenCanvas` (or `document.createElement('canvas')` for Safari < 16.4). Request a 2D context with `{ willReadFrequently: false, alpha: true }`. This flag tells Skia/Blink "this is a GPU upload target, don't keep a CPU copy."
2. **Clear:** `clearRect` on the offscreen buffer. This is a GPU `glClear`—nanoseconds.
3. **Emit:** Draw *only* glowing sprites/particles/UI to the offscreen buffer. Your game logic already knows what glows. Don't draw the whole scene.
4. **Blur (Pass 1):** Set `filter = 'blur(Npx)'` on the *offscreen* context. Draw the buffer onto itself (`drawImage(buffer, 0, 0)`). This is a horizontal+vertical separable pass approximated by the browser's internal shader.
5. **Blur (Pass 2, optional):** Repeat step 4 for larger radius without artifacting. Two passes at 16px ≈ one pass at 32px, but cheaper.
6. **Reset:** `filter = 'none'` on offscreen context. Clean state for next frame.
7. **Composite:** On *main* context: `globalCompositeOperation = 'lighter'` (additive blend), `globalAlpha = intensity`.
8. **Blit:** `drawImage(bloomBuffer, 0, 0)`. One texture bind, one draw call. Restore main context state.

The main context never sees `filter`. Never sees `globalAlpha` except for this one blit. The compositor caches the main canvas texture indefinitely.

## Core Concepts

### The Offscreen Buffer as GPU Texture
When you create a canvas with `willReadFrequently: false` (the default, but be explicit), Chrome's Skia backend allocates a `GrBackendTexture` backed by `GL_TEXTURE_2D` / `MTLTexture` / `ID3D11Texture2D`. It lives in VRAM. `drawImage` between two such canvases becomes a `glBlitFramebuffer` or equivalent—zero system memory copy.

### Ping-Pong Self-Blur
`bctx.drawImage(bloomBuffer, 0, 0)` while `filter: blur()` is active reads the *previous* frame's content (or the current frame's emissive draw) and writes blurred pixels back to the same texture. It's a feedback loop. One iteration = ~2σ Gaussian. Two iterations = ~4σ. Cheaper than a large kernel because the browser's blur shader is separable and fixed-cost per pass.

### Additive Compositing (`lighter`)
`globalCompositeOperation = 'lighter'` implements `dst + src` (clamped to 1.0). This *is* the bloom equation: `final = scene + bloom * intensity`. No custom shader math. The GPU's blend unit does it in fixed-function hardware.

### Luminance Thresholding Without Pixel Reads
You don't need `getImageData` or a fragment shader to threshold. Draw your emissive layer normally. Then:
```javascript
bctx.globalCompositeOperation = 'destination-in';
bctx.drawImage(thresholdMask, 0, 0); // White = keep, Black = kill
bctx.globalCompositeOperation = 'source-over';
```
`destination-in` keeps only where the mask is opaque. Generate `thresholdMask` once at startup: a radial gradient, a noise texture, or a grayscale+contrast filter pass on a cached sprite sheet.

## Examples & Code Walkthrough

Here is the production-grade implementation from our latest engine. Typescript, defensive, zero allocations in the hot path.

```typescript
// bloom.ts
// Persistent resources — allocated ONCE at startup
interface BloomRenderer {
  buffer: OffscreenCanvas | HTMLCanvasElement;
  ctx: OffscreenCanvasRenderingContext2D | CanvasRenderingContext2D;
  width: number;
  height: number;
  blurRadius: number;
  intensity: number;
  passes: 1 | 2;
  thresholdMask?: HTMLCanvasElement; // Optional luminance mask
}

export function createBloomRenderer(
  width: number,
  height: number,
  options: Partial<Pick<BloomRenderer, 'blurRadius' | 'intensity' | 'passes'>> = {}
): BloomRenderer {
  // OffscreenCanvas preferred (worker-transferable, no DOM overhead).
  // Fallback to hidden canvas for Safari < 16.4 / Firefox.
  const buffer = typeof OffscreenCanvas !== 'undefined'
    ? new OffscreenCanvas(width, height)
    : document.createElement('canvas');

  if (!(buffer instanceof OffscreenCanvas)) {
    buffer.width = width;
    buffer.height = height;
  }

  const ctx = buffer.getContext('2d', {
    willReadFrequently: false, // Critical: "GPU-only texture"
    alpha: true,
    desynchronized: true,      // Hint: reduce latency on composited displays
  });

  if (!ctx) throw new Error('2D context unavailable');

  return {
    buffer,
    ctx,
    width,
    height,
    blurRadius: options.blurRadius ?? 16,
    intensity: options.intensity ?? 0.35,
    passes: options.passes ?? 2,
  };
}

/**
 * Resize handler — call from your resize observer.
 * Re-allocates GPU texture. Expensive! Debounce.
 */
export function resizeBloom(renderer: BloomRenderer, w: number, h: number): void {
  if (renderer.width === w && renderer.height === h) return;
  renderer.width = w;
  renderer.height = h;

  if (renderer.buffer instanceof OffscreenCanvas) {
    renderer.buffer.width = w;
    renderer.buffer.height = h;
  } else {
    (renderer.buffer as HTMLCanvasElement).width = w;
    (renderer.buffer as HTMLCanvasElement).height = h;
  }
  // No need to re-get context; it's bound to the canvas.
}

/**
 * The hot path. 8 lines of actual work + state hygiene.
 * @param mainCtx The primary canvas context (your game canvas)
 * @param drawEmissive Callback that draws glowing objects to a context
 */
export function renderBloom(
  renderer: BloomRenderer,
  mainCtx: CanvasRenderingContext2D,
  drawEmissive: (ctx: CanvasRenderingContext2D) => void
): void {
  const { ctx, width, height, blurRadius, intensity, passes, thresholdMask } = renderer;

  // 1. Clear buffer (GPU clear)
  ctx.clearRect(0, 0, width, height);

  // 2. Draw emissive layer ONLY
  drawEmissive(ctx);

  // 3. Optional: Luminance threshold via blend mode (no pixel readback)
  if (thresholdMask) {
    ctx.globalCompositeOperation = 'destination-in';
    ctx.drawImage(thresholdMask, 0, 0, width, height);
    ctx.globalCompositeOperation = 'source-over';
  }

  // 4. Blur passes (ping-pong self-blur)
  ctx.filter = `blur(${blurRadius}px)`;
  for (let i = 0; i < passes; i++) {
    ctx.drawImage(renderer.buffer, 0, 0); // Reads previous, writes blurred
  }
  ctx.filter = 'none';

  // 5. Additive composite to main
  mainCtx.globalCompositeOperation = 'lighter';
  mainCtx.globalAlpha = intensity;
  mainCtx.drawImage(renderer.buffer, 0, 0);

  // 6. Restore main context state (DEFENSIVE: prevents bleeding into UI/HUD)
  mainCtx.globalCompositeOperation = 'source-over';
  mainCtx.globalAlpha = 1.0;
}
```

**Usage in your game loop:**

```typescript
// game.ts
const bloom = createBloomRenderer(canvas.width, canvas.height, {
  blurRadius: 24,
  intensity: 0.4,
  passes: 2,
});

// Pre-bake a threshold mask (radial falloff) — do this ONCE
const thresholdMask = document.createElement('canvas');
thresholdMask.width = canvas.width;
thresholdMask.height = canvas.height;
const mctx = thresholdMask.getContext('2d')!;
const grad = mctx.createRadialGradient(
  canvas.width / 2, canvas.height / 2, 0,
  canvas.width / 2, canvas.height / 2, Math.max(canvas.width, canvas.height) / 2
);
grad.addColorStop(0, 'white');
grad.addColorStop(0.6, 'white');
grad.addColorStop(1, 'black');
mctx.fillStyle = grad;
mctx.fillRect(0, 0, canvas.width, canvas.height);
bloom.thresholdMask = thresholdMask;

function gameLoop() {
  // 1. Clear main
  mainCtx.clearRect(0, 0, canvas.width, canvas.height);

  // 2. Draw opaque scene (background, tiles, non-glowing entities)
  drawScene(mainCtx);

  // 3. Bloom pass — draws emissive layer, blurs, adds to main
  renderBloom(bloom, mainCtx, (bctx) => {
    drawPlayerGlow(bctx);      // Ship engine, weapon charge
    drawParticleSystems(bctx); // Explosions, magic
    drawNeonUI(bctx);          // Holograms, scanlines
  });

  // 4. Draw UI/HUD on top (NO bloom contamination)
  drawHUD(mainCtx);

  requestAnimationFrame(gameLoop);
}
```

**Key defensive details:**
- `drawEmissive` callback isolates *what* glows from *how* it blooms. Your entity system passes a filtered draw call.
- State restoration (`source-over`, `alpha=1`) is non-negotiable. Miss it once and your health bar glows.
- `desynchronized: true` on context creation reduces latency on Windows/DirectComposition and macOS/Metal. No downside.
- Threshold mask is a *canvas*, not an ImageData. Stays on GPU.

## Best Practices

1. **One buffer per bloom "style."** Need a tight UI glow (4px) and a massive screen flash (64px)? Two buffers. Don't resize or change `filter` mid-frame—that forces shader recompilation in the compositor.
2. **Debounce resize.** `resizeBloom` reallocates VRAM. Throttle to 250ms or use `ResizeObserver` with `requestAnimationFrame` coalescing.
3. **Clamp intensity per scene.** `intensity: 0.35` works for neon. `0.15` for subtle magic. Expose as data-driven config, not hardcode.
4. **Prefer `OffscreenCanvas`.** It detaches from the DOM, enables `transferControlToOffscreen` for Web Workers later, and avoids style/layout thrashing.
5. **Profile on integrated graphics.** MacBook Air M1 ≠ Intel UHD 620. Test on the latter. `chrome://gpu` → "Canvas: Hardware accelerated" must be true.

## Common Mistakes & Anti-Patterns

### 1. Blurring the Main Context (The "Frame Killer")
```javascript
// ❌ WRONG: Main context filter toggle every frame
mainCtx.filter = 'blur(20px)';
mainCtx.drawImage(scene, 0, 0);
mainCtx.filter = 'none';
mainCtx.drawImage(scene, 0, 0);
```
**Why it kills you:** Every `filter` assignment marks the canvas layer "dirty." The compositor must re-rasterize the *entire* layer tree—text, images, transforms—into a new GPU texture. On a 1920×1080 canvas, that's ~8MB VRAM upload + shader dispatch *per frame*.

**Fix:** Move blur to offscreen buffer. Main context stays `filter: 'none'` forever.

### 2. Allocating Buffer Per Frame
```javascript
// ❌ WRONG: GC pressure + VRAM churn
function render() {
  const temp = document.createElement('canvas');
  // ...
}
```
**Why it kills you:** Triggers minor GC every frame. On mobile Safari, this janks at 30fPS. VRAM fragmentation.

**Fix:** `createBloomRenderer` once at init. `resizeBloom` only on actual size change.
