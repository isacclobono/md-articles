# Securely Authenticate Users with the Telegram Login Widget in PHP and Yii2

## Introduction

The Telegram Login Widget has become a popular shortcut for adding Telegram accounts to web applications with minimal friction. One click, a session established, and users feel instantly connected. Yet beneath this convenience lies a critical architectural decision: treating the incoming Telegram payload as implicitly trusted is a vulnerability waiting to be exploited. In our production environment, we encountered repeated incidents where malicious payloads bypassed naive validation checks, leading to unauthorized account takeovers and data integrity violations. 

This article presents a zero-trust authentication architecture built on Yii2 that transforms the Telegram Login Widget from a convenient shortcut into a rigorously verified entry point. Instead of assuming the widget is safe, we implement a layered verification system that cryptographically confirms each user's identity before granting access to protected resources.

## Why This Matters

Authentication is often the linchpin of secure application design. When developers integrate third-party widgets, they frequently make the mistake of placing trust blindly in client-side tokens or relying solely on the widget's native claims. Such approaches create single points of failure that can compromise the entire system. By implementing a dedicated verification layer in Yii2, we ensure that every authentication event passes multiple independent checks: cryptographic validation of the telegram payload, business-logic resolution of user identities, and continuous monitoring for anomalies. This pattern scales horizontally across distributed deployments while maintaining strong isolation between authentication concerns and application logic.

The architecture follows the Verifier-Resolver pattern, separating pure cryptographic operations from business logic. The `TelegramPayloadVerifier` component handles all message integrity checks independently, allowing it to be unit-tested without any database dependencies. The `IdentityResolver` then performs the stateful lookup against the Yii2 user collection, updating profiles or creating new accounts based on the verified identity. This separation ensures that even if the verifier is compromised, the resolver remains a controlled, role-bound operation.

## Core Concepts

Our implementation centers around three primary abstractions designed to enforce strict security boundaries:

**TelegramPayloadVerifier** constitutes the cryptographic foundation. It receives the serialized JSON payload returned by Telegram after the user authorizes the connection and provides constant-time comparison using `hash_equals()` to verify that the embedded `hash` matches the computed HMAC-SHA256 value derived from the bot token. Before proceeding beyond the cryptographic check, the verifier enforces a freshness constraint by rejecting tokens older than the configured maximum authorization age, which we set to five minutes for high-risk contexts.

**IdentityResolver** bridges the gap between external telegram identifiers and internal Yii2 user records. This component implements a deterministic mapping strategy: when a new Telegram ID arrives, it attempts to find an existing user record; upon success, it creates a linked profile association; upon failure, it initiates a conflict resolution flow that requires additional confirmation. The resolver emits domain events throughout this process to support audit trails and analytics.

**VerifiedTelegramDto** serves as the contract between layers. It encapsulates only the fields that are safe to persist directly into the database—specifically the opaque telegram ID, normalized name fields, and a sanitized avatar URL. Sensitive or potentially dangerous inputs such as raw photo URLs are stripped or transformed at the boundary to prevent storage-related vulnerabilities.

Each component depends exclusively on its immediate collaborators through interface contracts, enabling loose coupling and facilitating independent testing and deployment cycles.

### 1. Cryptographic Verification Service

The verifier encapsulates all aspects of hash verification without touching the database. It relies on a static configuration array containing the bot's API token, providing a self-contained verification unit that can be initialized once at application startup and injected wherever needed.

```php
<?php

namespace App\Services\Telegram;

use Yii\Base\Config;
use Symfony\Component\HttpFoundation\Request,
  HttpResponse,
  HttpException;
use Symfony\Component\HttpFoundation\Session\Session;

/**
 * Handles cryptographic verification of Telegram Login Widget payloads.
 *
 * Implements zero-trust validation by never accepting unverified strings.
 */
class TelegramPayloadVerifier
{
    /** @var string The BotFather API token used to compute HMAC */
    private const BOT_TOKEN = Config::get('telegram.bot_token');

    /**
     * Verify a fully deserialized Telegram authentication payload.
     *
     * @param array $payload The serialized JSON received from /telegram/callback
     * @return \Exception On invalid payload or failed verification
     */
    public function verify(array $payload): \Exception
    {
        // Validate basic structure before attempting crypto operations
        if (!is_array($payload)) {
            throw new \InvalidArgumentException(
                'Payload must be an associative array'
            );
        }

        // Require mandatory fields for successful Telogram login
        $requiredKeys = ['token', 'auth_date', 'username', 'first_name', 'last_name'];
        foreach ($requiredKeys as $key) {
            if (!array_key_exists($key, $payload)) {
                throw new \InvalidArgumentException(
                    sprintf('Missing required field "%s" in telegram payload', $key)
                );
            }
        }

        // Compute expected HMAC using SHA256 as the derivation function
        $computedHash = self::compute_hmac($this->BOT_TOKEN, $payload);

        // Use constant-time comparison to prevent timing attacks
        if !self::constant_time_compare($payload['hash'], $computedHash)) {
            throw new \RuntimeException(
                'Hash mismatch – possible replay attack detected',
                500
            );
        }

        return null;
    }

    /**
     * Computes HMAC-SHA256 of the payload using the bot token as key.
     */
    private function compute_hmac(string $key, array $payload): string
    {
        // Serialize the payload with JSON_UNESCAPED_SLASHES to preserve formatting
        $serializable = json_encode($payload, JSON_UNESCAPED_SLASHES | JSON_UNESCAPED_NEWLINE);
        
        // Encrypt with SHA256
        return hash('sha256', $serializable . $key, true);
    }

    /**
     * Performs constant-time string comparison resistant to timing side channels.
     */
    private static function constant_time_compare(string $expected, string $actual): bool
    {
        return hash_equals($expected, $actual);
    }

    /**
     * Optional configurable window in seconds for valid authentication tokens.
     * Default is 300 seconds (5 minutes) for sensitive tenant environments.
     *
     * @return int Maximum age of authorized authentication token
     */
    public const MAX_AUTH_AGE = 300;
}
```

### 2. Identity Resolution and User Management

The `IdentityResolver` translates validated Telegram credentials into authoritative user entities within the Yii2 framework. It maintains transactional consistency by leveraging Yii2's active record capabilities and emits domain events for observability.

```php
<?php

namespace App\Components\Telegram;

use App\Models\User;
use App\Events\UserLinkedEvent;
use App\Events\UserCreatedViaTelegramEvent;
use yii\base\Component;
use yii\web\Results;
use yii\session\Session;

/**
 * Resolves a verified Telegram credential to an existing or new Yii2 user.
 *
 * Implements a state machine that handles three distinct scenarios:
 * 1. New Telegram ID not yet known → Create new user and link via Telegram
 * 2. Existing Telegram ID found → Load user and update profile metadata
 * 3. Conflict scenario → Trigger manual intervention workflow
 */
class IdentityResolver extends Component
{
    public function resolve(\App\Telegram\TelegramDto $telegramDto): \User
    {
        $botToken = \App\Services\Telegram\TelegramPayloadVerifier::class::getInstance();
        $verifier = new \TelegramPayloadVerifier();

        try {
            // Early exit if payload fails cryptographic verification
            if ($verifier->verify($telegramDto->data) === null) {
                throw new \RuntimeException(
                    'Invalid telegram payload – authentication rejected',
                    401
                );
            }

            // Apply freshness policy before further processing
            if ((int)$telegramDto->data->get('auth_date') < 
                time() - \TelegramPayloadVerifier::MAX_AUTH_AGE) {

                throw new \RuntimeException(
                    'Token expired – contact support to renew Telegram integration',
                    401
                );
            }

            // Attempt to locate user by Telegram ID in the Yii2 collection
            $existingUser = \User::findOneByTelegramId($telegramDto->id);

            switch ($existingUser ?: false) {
                case true:
                    // Scenario B: Known Telegram ID – update profile information
                    $resolvedUser = $existingUser->update([
                        'first_name' => $telegramDto->name ?? '',
                        'last_name' => $telegramDto->name ?? '',
                        'avatar_url' => $telegramDto->avatarUrl ?? null,
                        'telegram_id' => $telegramDto->id,
                        'verified_via_telegram' => true,
                    ]);

                    // Emit event for downstream consumers
                    $this->onLinking($resolvedUser, 'User updated via Telegram');
                    break;

                case false:
                    // Scenario A: New Telegram ID – create user and establish link
                    $this->onLinking(null, 'New account created via Telegram');
                    
                    $newUser = \User::create([
                        'name' => $this->sanitize_input($telegramDto->name),
                        'email' => $this->extract_email_from_metadata($telegramDto),
                        'telegram_id' => $telegramDto->id,
                        'verified_via_telegram' => true,
                        'created_by' => \Yii::app->entryPoint->getRequest()->author(),
                    ]);

                    // Establish relationship – typically via a virtual table or foreign key
                    \User::linkByTelegramId($newUser, $telegramDto->id);

                    $this->onLinking($newUser, 'Account created via Telegram');
                    break;

            }

            return $resolvedUser;

        } catch (\InvalidArgumentException $e) {
            // Malformed request – handled upstream
            throw $e;
        }
    }

    /**
     * Sanitizes user-provided name fields to prevent XSS and storage vulnerabilities.
     *
     * @param string|null $name The raw name from Telegram payload
     * @return string The sanitized name ready for database storage
     */
    private function sanitize_input(?string $name): string
    {
        if ($name === null || empty($name)) {
            return '';
        }

        // Strip tags and normalize whitespace
        return trim(preg_replace('/<[^>]*>/u', '', $name));
    }

    /**
     * Extracts email address from Telegram metadata if available.
     *
     * Note: The official API does not guarantee email presence,
     * so this is optional and may return null.
     */
    private function extract_email_from_metadata(\App\Telegram\TelegramDto $telegramDto): ?string
    {
        // Some configurations embed email in custom fields
        // This is non-deterministic and should be documented
        return $telegramDto->get('email')
            ?? $telegramDto->data['extra']['email']
            ?? null;
    }

    /**
     * Hooks fired when a new account is linked via Telegram.
     *
     * Allows analytics pipelines, notification services, and audit systems to react.
     */
    protected function onLinking(\User $user, string $eventType): void
    {
        \Yii::active()->push(
            Yii::active()->getStack()
                ->register('telegram_linkage', [
                    'user_id' => $user->id,
                    'event_type' => $eventType,
                    'timestamp' => date('Y-m-d H:i:s'),
                    'source_ip' => \Yii::app->request->getClientIp(),
                ])
        );
    }
}
```

### 3. Controller Integration and Callback Handler

The controller acts as the thin orchestration layer between the web server and our verification services. It manages the lifecycle of the OAuth callback, coordinates state management via Redis, and applies proper sanitization before any user data touches the database.

```php
<?php

use Yii\Base\Controller;
use Yii\Helpers\Html;
use Yii\Session;
use Yii\Widgets\View\Helper\UrlHelper;
import \App\Components\Telegram\IdentityResolver;
import \App\Services\Telegram\TelegramPayloadVerifier;

/**
 * Handles the Telegram Login Widget callback and subsequent authentication workflow.
 */
class TelegramAuthController extends \Controller
{

        parent::__construct();

     * - State tokens are stored in Redis rather than session storage to avoid

            if ($verifier->verify($telegramDto->data) === null) {
