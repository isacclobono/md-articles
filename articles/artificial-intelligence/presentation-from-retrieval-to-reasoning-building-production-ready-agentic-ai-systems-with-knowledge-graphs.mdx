   # Presentation: From Retrieval to Reasoning: Building Production-Ready Agentic AI Systems with Knowledge Graphs

   ## Introduction
   Over the past year, my team has been operationalizing agentic workflows that sit between a user prompt and a set of backend services. The core tension is simple: LLMs are good at pattern completion, but production systems require deterministic reasoning, traceability, and context that doesn't drift. Knowledge graphs have emerged as a practical structure for encoding relationships, enforcing constraints, and providing a deterministic anchor for retrieval. This article walks through the architecture we built to move from naive retrieval to a reasoning loop that can be monitored, tested, and scaled.

   ## Why This Matters
   In production, an LLM that simply scrapes the web or queries a vector index without structure quickly becomes a black box. We've seen incidents where generated references were stale, edge cases triggered uncontrolled tool calls, and audit trails vanished. A knowledge graph gives us a fixed schema of entities and relationships, which means every hop the agent takes can be validated, cached, and replayed. For teams operating in regulated domains or dealing with high-cardinality data, this isn't a nice-to-have; it's the difference between a prototype and a service you can ship with confidence.

   ## How It Works
   ```mermaid
   flowchart TD
   A[User Query] --> B[Intent Classifier]
   B --> C[KG Entity Resolution]
   C --> D{Entity Graph Available?}
   D -->|Yes| E[Subgraph Extraction]
   D -->|No| F[Fallback Vector Retrieval]
   E --> G[Reasoning Loop]
   F --> G
   G --> H[Tool Decision]
   H --> I[Execution]
   I --> J[Response Builder]
   J --> K[User]
   ```

   The diagram above captures the high‑level data flow. Let me walk through each node. The process starts when a user submits a natural‑language query. An intent classifier (a lightweight model or rule‑based system) extracts the primary domain and requested action. Next, the system attempts entity resolution against the knowledge graph. If the graph contains the relevant nodes and edges, a subgraph is extracted—this is a critical step because it limits the reasoning scope and prevents the agent from wandering into unrelated domains. If the graph lacks coverage, a vector retrieval fallback kicks in, and the system marks the session for human review. The reasoning loop then uses the extracted context to decide on tool calls, enforce constraints, and finally hand off to a response builder that formats the output for the user.

   ## Core Concepts
   The architecture rests on three pillars. First, the **graph store**—in our setup, a Neo4j instance with a curated schema of entity types (e.g., Service, Deployment, Incident) and relationship types (e.g., DEPENDS_ON, OWNED_BY). Second, the **retrieval layer**, which operates in two modes: exact match on node identifiers and fuzzy match on property values. Third, the **agent loop**, which is a stateless function that receives the current subgraph, a prompt template, and a set of allowed tools. The loop decides whether to query the graph again, call an external API, or terminate. Crucially, every iteration logs the graph snapshot, the LLM’s reasoning trace, and the tool output. This log structure is what makes the system auditable and allows us to replay failures without re-invoking the LLM.

       """Represents a node in the knowledge graph."""
       id: str
       type: str  # e.g., "service", "instance", "incident"
       properties: Dict[str, object] = field(default_factory=dict)

   @dataclass
   class Relationship:
       """Represents a directed edge between two entities."""
       source: str
       target: str
       label: str  # e.g., "depends_on", "triggers"

   class KnowledgeGraph:
       """Simple in‑memory graph with basic traversal and query methods."""
       def __init__(self) -> None:
           self._nodes: Dict[str, Entity] = {}
           self._adj: Dict[str, List[Relationship]] = {}  # source -> outgoing edges

       def upsert_entity(self, entity: Entity) -> None:
           """Insert or update a node. Defensively copies properties to avoid
           external mutation."""
           self._nodes[entity.id] = Entity(
               id=entity.id,
               type=entity.type,
               properties=dict(entity.properties),  # shallow copy
           )
           self._adj.setdefault(entity.id, [])

       def add_relationship(self, rel: Relationship) -> None:
           """Add a directed relationship. Validates that both endpoints exist."""
           if rel.source not in self._nodes:
               raise ValueError(f"Source entity {rel.source} not found in graph")
           if rel.target not in self._nodes:
               raise ValueError(f"Target entity {rel.target} not found in graph")
           self._adj.setdefault(rel.source, []).append(rel)

       def get_neighbors(self, entity_id: str, relationship_type: Optional[str] = None) -> List[Relationship]:
           """Return outgoing relationships for a node. Returns empty list if node missing."""
           if entity_id not in self._nodes:
               logger.warning("Querying missing entity %s", entity_id)
               return []
           edges = self._adj.get(entity_id, [])
           if relationship_type:
               return [e for e in edges if e.label == relationship_type]
           return edges

       def query_path(self, start: str, goal: str, max_hops: int = 3) -> Optional[List[str]]:
           """Breadth‑first search up to max_hops. Returns a path of entity ids or None."""
           if start not in self._nodes or goal not in self._nodes:
               return None

           queue: List[tuple[str, List[str]]] = [(start, [start])]
           while queue:
               current, path = queue.pop(0)
               if current == goal:

                   if next_node not in visited:
                       visited.add(next_node)
                       queue.append((next_node, path + [next_node]))
           return None
