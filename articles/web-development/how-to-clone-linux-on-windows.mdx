# How to clone Linux on Windows

## Introduction

Last week, a senior engineer on my team bricked their WSL2 Ubuntu instance halfway through a `glibc` upgrade. No snapshots. No backups. Just a corrupted `/usr/lib` and a looming deadline. We recovered them in twelve minutes—not by reinstalling, but by importing a pristine `.tar` export we'd taken the previous Friday.

"Cloning Linux on Windows" sounds like a category error. Linux runs on bare metal; Windows runs on... Windows. But in 2024, the boundary is virtualized. Whether you're managing a fleet of WSL2 development environments, migrating a production database replica to a local Windows workstation for debugging, or imaging a physical Linux disk attached via USB, the mechanics are distinct from `cp -a`. You're dealing with VHDX internals, ext4 metadata, Windows registry keys, and the subtle semantics of sparse files on NTFS versus ReFS.

This article covers the three production-grade paths I trust: WSL2 distribution cloning (the daily driver), raw block-level imaging via `dd` inside WSL (the heavy lifter), and Clonezilla live media (the bare-metal escape hatch).

## Why This Matters

Web development environments have calcified into complex dependency graphs: specific Node versions, `systemd`-managed PostgreSQL, custom `nginx` modules, and kernel parameters tuned for `io_uring`. Reproducing this via `Dockerfile` or `ansible-playbook` takes forty minutes on a cold machine. Cloning a verified, working instance takes ninety seconds.

The pain points are real:
*   **WSL2 Registry Rot**: Unregistering a distro via `wsl --unregister` nukes the registry entry but often leaves the VHDX file behind, consuming 40GB+ on `C:\`.
*   **VHDX Compaction Failure**: `wsl --manage <distro> --set-sparse true` helps, but only if the filesystem inside the VHDX actually discarded blocks (requires `fstrim` / `discard` mount options).
*   **UID/GID Drift**: Cloning a distro to a new name preserves the internal UID map, but integrating with Windows file permissions (`/mnt/c`) via `metadata` mount options requires `/etc/wsl.conf` tuning *before* the clone.

If you treat your local Linux environment as cattle, not pets, you need a cloning workflow that is scriptable, verifiable, and doesn't require a reboot.

## How It Works

The core mechanism differs by layer.

**WSL2 Export/Import** operates at the filesystem tar layer. `wsl --export` streams the rootfs (excluding `/mnt`, `/proc`, `/sys`, `/dev`) through a tar pipe. `wsl --import` writes that stream into a *new* VHDX (or a directory on older WSL1), registering a new GUID in `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss`.

**Block-Level Cloning (`dd`/`ddrescue`)** operates on the VHDX file itself (or a physical `/dev/sdX` passed through). This copies the partition table, the ext4 superblock, UUIDs, and *deleted* data. It is faster for massive disks but carries the source's fragmentation and free space.

**Clonezilla** boots a minimal Linux kernel (via WinPE/GRUB or Ventoy) to image physical disks attached to the Windows host, bypassing the NTFS layer entirely.

**Step-by-Step: WSL2 Filesystem Clone (The Standard Path)**
1.  **Quiesce**: Stop services (`systemctl stop postgresql`), run `sync`, `fstrim -v /` inside the source distro.
2.  **Export**: `wsl --export Ubuntu-22.04 ./ubuntu-22.04-backup.tar` (streams rootfs to stdout/file).
3.  **Verify**: `tar -tvf ./ubuntu-22.04-backup.tar | head -20` (check for symlinks, permissions).
4.  **Import**: `wsl --import Ubuntu-Clone ./install-dir ./ubuntu-22.04-backup.tar --version 2`.
5.  **Configure**: Set default user via `/etc/wsl.conf` *inside the new distro* or `ubuntu-clone.exe config --default-user <name>`.
6.  **Validate**: Boot, check `df -h`, `systemctl status`, network connectivity.

## Core Concepts

### The VHDX Container
WSL2 stores the Linux root filesystem inside a dynamically expanding Virtual Hard Disk v2 (`.vhdx`). It sits at `%LOCALAPPDATA%\Packages\<PackageFamilyName>\LocalState\ext4.vhdx`.
*   **Sparse Allocation**: The VHDX reports a maximum size (default 256GB/1TB) but consumes only written blocks on the host NTFS/ReFS.
*   **Block Discard (TRIM)**: Critical for reclaiming space. The kernel must issue `BLKDISCARD` (via `fstrim` or `discard` mount opt) for the VHDX to shrink on host. Without this, a 50GB clone of a 10GB used distro stays 50GB on disk.

### The Registry Identity
`HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss\{GUID}` maps a friendly name to the VHDX path, default UID, kernel command line, and environment variables. `wsl --import` generates a *new* GUID. This is why cloned distros are distinct entities—they don't share the same registry key.

### Filesystem Semantics: `metadata` vs `drvfs`
When cloning, the `/etc/wsl.conf` `[automount]` options dictate how Windows files appear inside Linux.
*   `options = "metadata,uid=1000,gid=1000,umask=022,fmask=022"`: Enables `chmod`/`chown` on `/mnt/c` by storing extended attributes (NTFS EAs).
*   **Cloning Trap**: If the source had `metadata` enabled, the tar archive contains those EAs. The target *must* mount with `metadata` enabled, or permission bits become misleading.

### Export Exclusions
`wsl --export` implicitly excludes:
*   Virtual filesystems: `/proc`, `/sys`, `/dev`, `/run`
*   Mount points: `/mnt/*`, `/media/*`
*   The swap file (usually `/swapfile` or dedicated partition)
It effectively performs a `tar --one-file-system --exclude=/mnt --exclude=/proc ...` on the root mount.

## Examples & Code Walkthrough

### 1. The "Golden Image" Pipeline (PowerShell + Bash)

This script automates the creation of a clean, trimmed, versioned WSL distro tarball suitable for CI/CD or team distribution. It handles the `fstrim` quiesce, exports with `zstd` compression (3x faster than gzip), and verifies the archive integrity.

**`New-WslGoldenImage.ps1`**
```powershell
<#
.SYNOPSIS
    Creates a verified, trimmed, compressed tarball of a WSL2 distribution.
    Designed for CI pipelines and developer onboarding.
#>
[CmdletBinding()]
param(
    [Parameter(Mandatory)][string]$SourceDistroName,
    [Parameter(Mandatory)][string]$OutputPath,
    [string]$CompressionLevel = "19", # zstd max
    [switch]$VerifyOnly
)

# 1. Validate Source Exists & Is WSL2
$distro = wsl -l -v | Where-Object { $_ -match "^\s*\*?\s+$SourceDistroName\s+" }
if (-not $distro) { Throw "Distro '$SourceDistroName' not found." }
if ($distro -notmatch "WSL2") { Throw "Source must be WSL2. Convert first: wsl --set-version $SourceDistroName 2" }

# 2. Quiesce & Trim (Run inside Linux)
Write-Host "[$(Get-Date)] Quiescing filesystem and running fstrim..." -ForegroundColor Cyan
$trimCmd = "sync; fstrim -v /; systemctl stop postgresql docker nginx 2>\$null; sync"
wsl -d $SourceDistroName -e bash -c $trimCmd
if ($LASTEXITCODE -ne 0) { Write-Warning "fstrim/service stop reported non-zero. Continuing..." }

# 3. Export Stream -> zstd
Write-Host "[$(Get-Date)] Exporting '$SourceDistroName' to '$OutputPath'..." -ForegroundColor Cyan
# wsl --export writes to stdout if output is '-', but we pipe to zstd for streaming compression
# Note: wsl --export does not support stdout directly in older versions. Use temp file if needed.
# Modern WSL (0.67.6+): wsl --export $SourceDistroName - | zstd -$CompressionLevel -T0 -o $OutputPath
# Robust fallback for current stable:
$tempTar = [IO.Path]::GetTempFileName() + ".tar"
try {
    wsl --export $SourceDistroName $tempTar
    # Compress with maximum threads, long distance matching for dedup
    & zstd -$CompressionLevel -T0 --long=27 -o $OutputPath $tempTar
    Write-Host "[$(Get-Date)] Compression complete. Size: $('{0:N2}' -f ((Get-Item $OutputPath).Length / 1GB)) GB" -ForegroundColor Green
}
finally {
    if (Test-Path $tempTar) { Remove-Item $tempTar -Force }
}

# 4. Verification
if ($VerifyOnly -or $true) { # Always verify in pipeline
    Write-Host "[$(Get-Date)] Verifying archive integrity..." -ForegroundColor Cyan
    # Test decompression + tar listing without full extraction
    & zstd -t $OutputPath
    if ($LASTEXITCODE -ne 0) { Throw "zstd integrity check failed." }
    
    # Spot-check critical files
    $check = & zstd -dc $OutputPath | tar -tzf - | Select-String -Pattern "^(etc/passwd|etc/wsl.conf|root/.bashrc|usr/bin/node)$"
    if ($check.Count -lt 3) { Throw "Archive missing critical rootfs files." }
    Write-Host "[$(Get-Date)] Verification passed." -ForegroundColor Green
}
```

**Usage:**
```powershell
# Build the image
.\New-WslGoldenImage.ps1 -SourceDistroName "Ubuntu-22.04-Base" -OutputPath ".\artifacts\ubuntu-22.04-base-$(Get-Date -Format 'yyyyMMdd').tar.zst"

# Deploy to new machine (Target Machine)
wsl --import Team-Ubuntu $env:LOCALAPPDATA\WSL\Team-Ubuntu .\artifacts\ubuntu-22.04-base-20240515.tar.zst
# Fix default user (requires distro running once or editing /etc/passwd offline)
wsl -d Team-Ubuntu -u root sed -i 's/^\(ubuntu:x:1000:1000:.*\)$/ubuntu:x:1000:1000::\/home\/ubuntu:\/bin\/bash/' /etc/passwd
```

### 2. Block-Level Clone: `ddrescue` for VHDX Backup/Restore

When you need a bit-for-bit copy (preserving UUIDs, partition layout, deleted files for forensics, or cloning a dual-boot partition passed through via `wsl --mount`), `tar` is the wrong tool. `ddrescue` (GNU ddrescue) handles read errors gracefully and provides a mapfile for resumable copies.

**Prereq**: `sudo apt update && sudo apt install gddrescue` inside WSL.

**`clone-vhdx.sh`**
```bash
#!/usr/bin/env bash
# clone-vhdx.sh: Block-level clone of a WSL VHDX or physical disk passed to WSL.
# Usage: sudo ./clone-vhdx.sh /dev/source /mnt/d/backups/target.img.map

set -euo pipefail

SRC="${1:?Source block device (e.g. /dev/sdc or /mnt/wsl/ext4.vhdx)}"
DST_IMG="${2:?Destination image file path}"
MAP_FILE="${DST_IMG}.map"
LOG_FILE="${DST_IMG}.log"

# Safety: Refuse to write to source device
if [[ "$(readlink -f "$SRC")" == "$(readlink -f "$DST_IMG")" ]]; then
    echo "ERROR: Source and Destination resolve to same path." >&2
    exit 1
fi

# Check if source is mounted R/W - dangerous for block clone
if findmnt -rn -o SOURCE,TARGET "$SRC" | grep -v "ro,"; then
    echo "WARN: Source $SRC appears mounted R/W. Block clone may be inconsistent." >&2
    read -rp "Continue anyway? [y/N] " ans
    [[ "$ans" =~ ^[Yy]$ ]] || exit 1
fi

echo "[$(date)] Starting ddrescue: $SRC -> $DST_IMG"
echo "Mapfile: $MAP_FILE"

# Phase 1: Fast copy (skip errors, no retries yet)
# -n: no scrape (skip bad sectors initially)
# -f: force overwrite
# -T: timestamp in log
ddrescue -f -n -T "$SRC" "$DST_IMG" "$MAP_FILE" 2>&1 | tee -a "$LOG_FILE"

# Phase 2: Retry bad sectors (r3 = 3 retries), trim succeeded blocks
# -r3: retry bad sectors 3 times
# -t: trim (mark good sectors in mapfile to skip next run)
echo "[$(date)] Phase 1 done
