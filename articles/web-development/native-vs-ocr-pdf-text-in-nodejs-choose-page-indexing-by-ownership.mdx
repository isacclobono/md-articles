# Native vs OCR PDF Text in Node.js: Choose Page Indexing by Ownership

## Introduction
When a PDF arrives in your service you often reach for a text‑extraction library and assume the result is either “good enough” or you fall back to OCR. That binary view hides a richer signal: some pages were generated by your own code, others came from a scanner or a third‑party upload. Treating every page the same forces you to either sacrifice fidelity (by discarding vector metadata) or waste CPU (by OCR‑ing pages that already contain perfect text). The real decision isn’t which library to call; it’s how to route each page based on **provenance ownership**.

## Why This Matters
In production pipelines that ingest contracts, invoices, or user‑generated reports, the cost of a mis‑extracted character can be a failed compliance check, a mismatched invoice total, or a broken search index. Teams that blindly OCR everything see latency spikes and inflated cloud bills, while teams that trust native extraction blindly encounter ligature‑related bugs (“ﬁ” vs “fi”) and garbled reading order in multi‑column layouts. By making provenance a first‑class routing signal you gain:

* Deterministic, zero‑cost extraction for owned documents.
* Targeted, high‑confidence OCR only where the native layer is untrusted.
* A searchable index that can boost results based on extraction confidence.

## How It Works
The pipeline consists of three logical layers:

1. **Provenance Classification** – decide whether a page is *owned* (first‑party) or *unowned* (third‑party).
2. **Extraction** – pull text from the native layer when trusted, otherwise run OCR.
3. **Fusion & Indexing** – combine native semantic data with OCR spatial data when both are available, then store the result with provenance metadata.

Below is a flowchart that shows the per‑page decision process.

```mermaid
flowchart TD
    A[Start: PDF page] --> B{Is page owned?}
    B -->|Yes| C[Extract native text + embedded manifest]
    B -->|No| D[Run native extraction + heuristic classifier]
    D --> E{Classifier outcome}
    E -->|NATIVE_CLEAN| F[Use native text only]
    E -->|NATIVE_DIRTY| G[Extract native text + run OCR]
    E -->|SCAN_SUSPECT| H[Run full OCR]
    E -->|VECTOR_NOISE| I[Flag for human review]
    G --> J[Fuse native & OCR layers (spatial join)]
    F --> K[Produce ExtractionResult]
    J --> K
    H --> K
    I --> K
    K --> L[Index with provenance & confidence]
    L --> M[End]
```

**Step‑by‑step explanation**

1. **Ownership check** – If the PDF was generated by your service (e.g., via `pdfkit` or Puppeteer) you can trust that the native text layer is correct and that you have embedded a manifest at creation time. No further analysis is needed.
2. **Heuristic gatekeeper** – For unowned pages we first pull whatever native text exists (using `pdf-parse` or `pdfjs-dist`). A lightweight classifier inspects metrics such as character density, font variety, and image‑to‑vector ratio to decide whether the native layer is likely clean, dirty, a scan, or pure vector noise.
3. **Extraction paths** –  
   * *NATIVE_CLEAN*: accept the native text as final.  
   * *NATIVE_DIRTY*: keep the native text for its semantic richness (Unicode, font metrics) but run OCR to obtain authoritative bounding boxes.  
   * *SCAN_SUSPECT*: skip native text entirely and run OCR.  
   * *VECTOR_NOISE*: the page contains mostly CAD drawings or diagrams; we flag it for manual review because neither text nor OCR will yield useful content.
4. **Fusion** – When we have both native spans and OCR blocks we perform a spatial join: each native text span is mapped to the overlapping OCR block (if any). The OCR block supplies the precise bbox and rotation; the native span supplies the Unicode string and font style. Any OCR blocks that do not overlap a native span are kept as `OCR_EXCLUSIVE` (useful for handwritten notes or table cells that the native layer missed).
5. **Indexing** – The final `ExtractionResult` stores the page’s text, its provenance flag, a confidence score, and an array of bounding boxes. Search engines can boost results from `NATIVE_OWNED` pages and surface OCR‑suspect regions for a “view source” toggle.

## Core Concepts

### Page Provenance Ownership
* **First‑Party (Owned)** – PDFs emitted by your own services. You control the generation process and can embed extraction metadata at write time.
* **Third‑Party (Unowned)** – PDFs received from users, email, or external systems. You cannot guarantee the integrity of the native text layer.

### ExtractionResult Type
A discriminated union forces callers to handle each provenance case explicitly.

```ts
// types/extraction.ts
export enum TextProvenance {
  NATIVE_OWNED = 'NATIVE_OWNED',
  NATIVE_UNVERIFIED = 'NATIVE_UNVERIFIED',
  OCR_ENHANCED = 'OCR_ENHANCED',
  OCR_FALLBACK = 'OCR_FALLBACK',
}

export interface BaseResult {
  pageIndex: number;
  provenance: TextProvenance;
  confidence: number; // 0.0 – 1.0
}

export interface NativeOwned extends BaseResult {
  provenance: TextProvenance.NATIVE_OWNED;
  content: string;
  // No bbox needed – we trust the source layout.
}

export interface OCREnhanced extends BaseResult {
  provenance: TextProvenance.OCR_ENHANCED;
  content: string;
  bbox: { x: number; y: number; w: number; h: number; rotation: number }[];
}

export interface OCRFallback extends BaseResult {
  provenance: TextProvenance.OCR_FALLBACK;
  content: string;
  bbox: { x: number; y: number; w: number; h: number; rotation: number }[];
}

export type ExtractionResult =
  | NativeOwned
  | OCREnhanced
  | OCRFallback;
```

### Spatial Join Algorithm
The fusion step uses an R‑tree (via `rbush`) to quickly find the OCR block that overlaps a native text span.

```ts
// fusion/spatial-join.ts
import RBush from 'rbush';

interface OCRBlock {
  text: string;
  bbox: { x: number; y: number; w: number; h: number; rotation: number };
}

interface NativeSpan {
  text: string;
  font: string;
  bbox: { x: number; y: number; w: number; h: number };
}

/**
 * Returns an array of fused blocks. Native semantics win; OCR supplies geometry.
 */
export function fuseLayers(
  nativeSpans: NativeSpan[],
  ocrBlocks: OCRBlock[]
): Array<{
  text: string;
  font: string | undefined;
  bbox: { x: number; y: number; w: number; h: number; rotation: number };
}> {
  // Normalize to PDF points (1 point = 1/72 inch) – most libs already use this.
  const tree = new RBush<OCRBlock & { __id: number }>();
  ocrBlocks.forEach((b, i) => tree.insert({ ...b, __id: i }));

  const fused: ReturnType<typeof fuseLayers>[number][] = [];

  for const span of nativeSpans {
    const hits = tree.search({
      minX: span.bbox.x,
      minY: span.bbox.y,
      maxX: span.bbox.x + span.bbox.w,
      maxY: span.bbox.y + span.bbox.h,
    });

    if (hits.length === 0) {
      // No OCR overlap – keep native geometry, rotation = 0.
      fused.push({
        text: span.text,
        font: span.font,
        bbox: { x: span.bbox.x, y: span.bbox.y, w: span.bbox.w, h: span.bbox.h, rotation: 0 },
      });
      continue;
    }

    // Choose the OCR block with the largest overlap area.
    const best = hits.reduce((a, b) => {
      const overlapA = overlapArea(a, span.bbox);
      const overlapB = overlapArea(b, span.bbox);
      return overlapB > overlapA ? b : a;
    });

    fused.push({
      text: span.text,
      font: span.font,
      bbox: {
        x: best.x,
        y: best.y,
        w: best.w,
        h: best.h,
        rotation: best.rotation ?? 0,
      },
    });
    // Remove used OCR block to avoid double‑assigning.
    tree.remove({ __id: best.__id });
  }

  // Any remaining OCR blocks are exclusive (e.g., handwritten notes).
  tree.all().forEach(block => {
    fused.push({
      text: block.text,
      font: undefined,
      bbox: { x: block.x, y: block.y, w: block.w, h: block.h, rotation: block.rotation ?? 0 },
    });
  });

  return fused;
}

function overlapArea(
  a: { x: number; y: number; w: number; h: number },
  b: { x: number; y: number; w: number; h: number }
): number {
  const xOverlap = Math.max(0, Math.min(a.x + a.w, b.x + b.w) - Math.max(a.x, b.x));
  const yOverlap = Math.max(0, Math.min(a.y + a.h, b.y + b.h) - Math.max(a.y, b.y));
  return xOverlap * yOverlap;
}
```

## Examples & Code Walkthrough

Below is a simplified but complete pipeline that ties the concepts together. Error handling is kept explicit; production code would add retries, circuit breakers, and structured logging.

```ts
// pipeline/pdf-pipeline.ts
import PDFParser from 'pdf-parse';
import { classifyPage } from './classifiers/page-classifier';
import { extractNative } from './extractors/native-extractor';
import { runOcr } from './extractors/ocr-extractor';
import { fuseLayers } from './fusion/spatial-join';
import { ExtractionResult, TextProvenance } from '../types/extraction';
import { PageProcessedEvent } from '../observability/events';

export class PdfExtractionPipeline {
  /**
   * Process a single PDF page. Returns an ExtractionResult ready for indexing.
   */
  async processPage(pageBuffer: Buffer, pageIndex: number, isOwned: boolean): Promise<ExtractionResult> {
    // 1️⃣ Owned fast‑path
    if (isOwned) {
      const native = await extractNative(pageBuffer);
      const result: ExtractionResult = {
        pageIndex,
        provenance: TextProvenance.NATIVE_OWNED,
        confidence: 0.99, // near‑certain
        content: native.text,
      };
      this.emitEvent(result, native.latencyMs);
      return result;
    }

    // 2️⃣ Unowned: try native first, then decide.
    const native = await extractNative(pageBuffer);
    const classification = classifyPage({
      charCount: native.text.length,
      fontCount: native.fonts.length,
      glyphCoverage: native.glyphToUnicodeCoverage,
      imageRatio: native.imageArea / native.pageArea,
      vectorPathComplexity: native.vectorPathCount,
    });

    // 3️⃣ Branching based on classifier.
    switch (classification) {
      case 'NATIVE_CLEAN': {
        const res: ExtractionResult = {
          pageIndex,
          provenance: TextProvenance.NATIVE_UNVERIFIED,
          confidence: 0.85,
          content: native.text,
        };
        this.emitEvent(res, native.latencyMs);
        return res;
      }
      case 'NATIVE_DIRTY': {
        const ocr = await runOcr(pageBuffer);
        const fused = fuseLayers(native.spans, ocr.blocks);
        const content = fused.map(b => b.text).join(' ');
        const res: ExtractionResult = {
          pageIndex,
          provenance: TextProvenance.OCR_ENHANCED,
          confidence: 0.9,
          content,
          // In a real system we would attach the fused bbox array.
        };
        this.emitEvent(res, native.latencyMs + ocr.latencyMs);
        return res;
      }
      case 'SCAN_SUSPECT': {
        const ocr = await runOcr(pageBuffer);
        const content = ocr.blocks.map(b => b.text).join(' ');
        const res: ExtractionResult = {
          pageIndex,
          provenance: TextProvenance.OCR_FALLBACK,
          confidence: 0.7,
          content,
        };
        this.emitEvent(res, ocr.latencyMs);
        return res;
      }
      case 'VECTOR_NOISE': {
        // No meaningful text – return empty result with low confidence.
        const res: ExtractionResult = {
          pageIndex,
          provenance: TextProvenance.OCR_FALLBACK,
          confidence: 0.1,
          content: '',
        };
        this.emitEvent(res, 0);
        return res;
      }
      default:
        throw new Error(`Unknown page classification: ${classification}`);
    }
  }

  private emitEvent(result: ExtractionResult, latencyMs: number) {
    // In practice you’d send this to a tracing system (e.g., OpenTelemetry).
    const event: PageProcessedEvent = {
      pageIndex: result.pageIndex,
      provenance: result.provenance,
      latencyMs,
      charSourceRatio: result.content.length / 1000, // dummy metric
    };
    console.debug('[PdfPipeline] Page processed', event);
  }
}
```

**What the code demonstrates**

* **Ownership flag** (`isOwned`) lets us skip all heuristics for first‑party PDFs.
* **Classifier** returns a string discriminant that drives a clear switch statement—no magic strings hidden in config.
* **Fusion** only runs when we have both native and OCR data, avoiding unnecessary work.
* **Observability** is baked in: each page emits a timed event with provenance and latency.

## Best Practices

1. **Embed a manifest at generation time** – When you create a PDF with `pdfkit` or `puppeteer`, write a hidden XObject that contains a JSON map of `pageIndex → {textContent, fontMap, bbox}`. This turns extraction into an O(1) lookup and eliminates ligature guesswork.
2. **Keep the classifier dependency‑free** – A pure‑TypeScript function that runs on the extracted `pdf-parse` object adds virtually no latency and can be unit‑tested with fixtures.
3. **Fuse, don’t concatenate** – Always join on spatial overlap; concatenating creates duplicate tokens and destroys reading order, which hurts relevance scoring.
4. **Version your provenance enum** – If you ever add a new tier (e.g., `HUMAN_VERIFIED`), make it a new enum value and update all switch statements; TypeScript will warn you about missing cases.
5. **Metric‑driven OCR throttling** – Track average OCR latency per page type; if a tenant’s scan ratio spikes, automatically route those pages to a cheaper, asynchronous OCR worker pool.

## Common Mistakes & Anti‑Patterns

| Mistake | Why it hurts | Fix |
|---|---|---|
| **`if (text.length === 0) await ocr(page)`** | Ignores pages where native text exists but is garbage (e.g., missing ToUnicode map). You lose semantic clues and may OCR a perfectly good vector diagram. | Run the classifier first; only OCR when the classifier says `SCAN_SUSPECT` or `NATIVE_DIRTY`. |
| **Concatenating native + OCR text** | Produces duplicate tokens, skews term frequency, and destroys the original reading order (especially in multi‑column layouts). | Use the spatial join algorithm; keep one canonical token per visual region. |
| **Treating all pages as same confidence** | Search ranking becomes noisy; OCR‑suspect hits appear as relevant as owned documents, leading to false positives. | Store `provenance` and `confidence` fields; apply boost factors at query time (`NATIVE_OWNED: 2.0`, `OCR_ENHANCED: 1.5`, `OCR_FALLBACK: 0.8`). |
| **Skipping bbox storage** | You lose the ability to highlight the exact location of a term in the PDF UI, which is essential for “view source” features. | Persist the array of bounding boxes per `ExtractionResult` (or a compressed version). |
| **Running OCR on the whole document upfront** | Wastes CPU and money on pages that are already clean; increases latency for interactive APIs. | Make OCR a lazy, per‑page step triggered only by the classifier outcome. |
