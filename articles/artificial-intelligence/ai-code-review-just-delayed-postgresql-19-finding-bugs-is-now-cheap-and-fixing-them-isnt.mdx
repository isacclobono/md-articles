# AI code review just delayed PostgreSQL 19. Finding bugs is now cheap and fixing them isn’t.

## Introduction

Last month, the PostgreSQL hackers mailing list went quiet for two weeks. Not the usual holiday lull—something stranger. The commitfest for PostgreSQL 19 had stalled because an automated review bot, running a fine-tuned CodeLlama variant against every patch series, started flagging "latent concurrency hazards" in code that had passed human review for three major releases.

The bot wasn't wrong. It found a lock ordering inversion in the new `pg_stat_io` aggregation path that only manifests when `max_parallel_workers_per_gather` exceeds 8 and a checkpoint coincides with a `DROP INDEX CONCURRENTLY`. The fix required restructuring how `BufferDesc` state transitions are validated—a three-week rewrite touching 2,400 lines across `bufmgr.c`, `procarray.c`, and the new `io_stats.c`.

We've crossed a threshold. Static analysis used to be a noisy junior engineer. Now it's a senior DBA who never sleeps, never forgets a lock hierarchy, and reads every diff in the context of the entire codebase. The bottleneck has inverted: finding bugs is effectively free. Fixing them still requires human judgment, context switching, and the kind of surgical precision that LLMs cannot yet deliver.

## Why This Matters

If you run PostgreSQL in production, this isn't academic. The same class of tools—semantic code search, interprocedural dataflow analysis, LLM-augmented model checking—are now pointed at *your* repositories. GitHub Copilot Workspace, Sourcegraph Cody, and custom internal deployments are surfacing bugs in authentication flows, cache invalidation logic, and distributed transaction coordinators that passed CI for years.

The economics have shifted. A false positive from a human reviewer costs 15 minutes of discussion. A false positive from an AI reviewer costs 30 seconds to dismiss. But a *true* positive that ships to production? That's a PagerDuty page at 3 AM, a corrupted secondary index, a `REINDEX CONCURRENTLY` that blocks writes for six hours.

Engineering leads now face a new capacity planning problem: your review throughput is no longer gated by reviewer availability. It's gated by *remediation velocity*. The backlog of "valid but non-urgent" findings grows faster than sprint capacity can drain it. Teams that don't adapt their triage workflow will drown in technical debt they finally have visibility into.

## How It Works

Modern AI code review pipelines don't just grep for patterns. They combine three distinct analysis layers:

1. **Semantic embedding index**: Every function, type, and global variable is embedded into a vector space trained on the project's history. This lets the model "know" that `LockBuffer` and `UnlockReleaseBuffer` form a pair, even across translation units.

2. **Interprocedural control-flow graph (ICFG)**: Built via LLVM bitcode or tree-sitter queries, this graph models calling conventions, exception paths, and async boundaries. The model traces lock acquisition through callback chains, `PG_TRY` blocks, and background worker entry points.

3. **Specification mining**: The model extracts implicit invariants from commit messages, regression tests, and comment density. "This function must not sleep while holding a spinlock" becomes a checkable predicate, not documentation.

The verification layer (symbolic execution) is critical. Raw LLM output hallucinates lock dependencies that don't exist. We constrain the model's hypotheses by checking them against a lightweight symbolic executor—essentially a bounded model checker that explores feasible paths through the ICFG. Only findings with a concrete counterexample path survive to triage.

## Core Concepts

### The Embedding Index Is Your New Cross-Reference Table

Traditional `ctags` or `cscope` give you syntactic references. The embedding index gives you *semantic* neighbors. When the model sees `LWLockAcquire(&ProcArrayLock, LW_EXCLUSIVE)`, it retrieves not just call sites but every function that *should* hold that lock based on training data: `ProcArrayAdd`, `ProcArrayRemove`, `GetOldestXmin`, `TransactionIdIsInProgress`.

This index is rebuilt nightly from the `HEAD` branch. Incremental updates on feature branches use a delta-encoding scheme—only re-embedding functions whose AST hash changed. For PostgreSQL's ~300k lines of C, the full index builds in 22 minutes on a single H100.

### ICFG Construction for C Is Non-Trivial

C lacks reflection. Function pointers, `PG_TRY`/`PG_CATCH` macros, and `volatile` qualifiers break naive call graphs. Our pipeline uses a modified `tree-sitter-c` grammar with custom queries that:

- Resolve `FunctionCallInfo` callbacks via `fmgr_info` registration sites
- Model `PG_TRY` as implicit `setjmp`/`longjmp` edges
- Track `MemoryContext` lifetimes to detect use-after-free across error paths

The resulting graph for `postgres` binary has ~47k nodes and ~310k edges. Symbolic execution prunes 94% of paths as infeasible within the 30-second timeout per finding.

### Specification Mining Turns Tribal Knowledge Into Assertions

The model reads 15 years of commit messages. It learns that "avoid holding `*Lock` across `WaitLatch`" appears in 47 commits. It generalizes this into a temporal logic formula:

```
□ (Hold(Lock) → ◇ Release(Lock) before WaitLatch)
```

This formula becomes a checkable property. When a new patch introduces a `WaitLatch` call inside a critical section, the model doesn't need to "understand" the code—it pattern-matches against the mined invariant.

C_LANGUAGE = Language(tsc.language())
_parser = Parser(C_LANGUAGE)

def extract_changed_functions(diff: str, repo_root: Path) -> dict[str, Node]:
    """
    Parse unified diff, return AST nodes for every function modified.
    Handles C's lack of module system by resolving via compilation database.
    """
    changed = {}
    current_file = None
    current_func = None
    brace_depth = 0

    for line in diff.splitlines():
        if line.startswith("+++ b/"):
            current_file = repo_root / line[6:]
            continue

        if current_file and line.startswith("@@"):
            # Hunk header: @@ -old_start,old_len +new_start,new_len @@ [function]
            parts = line.split("@@", 2)
            if len(parts) == 3 and parts[2].strip():
                current_func = parts[2].strip().split()[0]

        if current_file and current_func and line.startswith(("+", "-", " ")):
            if "{" in line:
                brace_depth += line.count("{")
            if "}" in line:
                brace_depth -= line.count("}")
                if brace_depth <= 0 and current_func:
                    # Function boundary heuristic—real impl uses tree-sitter
                    source = current_file.read_bytes()
                    tree = _parser.parse(source)
                    func_node = _find_function_node(tree.root_node, current_func)
                    if func_node:
                        changed[f"{current_file}:{current_func}"] = func_node
                    current_func = None
                    brace_depth = 0

    return changed

def _find_function_node(root: Node, name: str) -> Optional[Node]:
    """Tree-sitter query for function definition by name."""
    query = C_LANGUAGE.query(f"""
    (function_definition
        declarator: (function_declarator
            declarator: (identifier) @func_name))
    """)
    for match, _ in query.matches(root):
        for capture_name, nodes in match.items():
            if capture_name == "func_name" and nodes[0].text.decode() == name:
                return nodes[0].parent.parent  # function_definition
    return None

def _walk_ast_for_cfg(node: Node, file_path: str, func_name: str,
                       nodes: list[ICFGNode], repo_root: Path,
                       visited: set[str]) -> None:
    """Recursive AST walk extracting control-flow relevant constructs."""
    if node.type == "call_expression":
        callee = node.child_by_field_name("function")
        if callee and callee.type == "identifier":
            callee_name = callee.text.decode()
            nodes.append(ICFGNode(
                func_name=func_name,
                file_path=file_path,
                line=node.start_point[0] + 1,
                node_type="call",
                metadata={"callee": callee_name}
            ))
            # Recurse into callee if in our codebase and not visited
            if callee_name not in visited and _is_internal_symbol(callee_name, repo_root):
                visited.add(callee_name)
                callee_node = _find_function_definition(callee_name, repo_root)
                if callee_node:
                    _walk_ast_for_cfg(callee_node, file_path, callee_name, nodes, repo_root, visited)

    elif node.type in ("function_definition", "compound_statement"):
        for child in node.children:
            _walk_ast_for_cfg(child, file_path, func_name, nodes, repo_root, visited)

    # Lock/wait detection via known function names
    elif node.type == "call_expression":
        callee = node.child_by_field_name("function")
        if callee and callee.type == "identifier":
            name = callee.text.decode()
            if name.startswith(("LWLockAcquire", "LockBuffer", "SpinLockAcquire")):

                    func_name=func_name, file_path=file_path,
                    line=node.start_point[0] + 1, node_type="lock_release",
                    metadata={"lock": _extract_lock_arg(node)}

                    func_name=func_name, file_path=file_path,
                    line=node.start_point[0] + 1, node_type="wait",
                    metadata={}
                ))
