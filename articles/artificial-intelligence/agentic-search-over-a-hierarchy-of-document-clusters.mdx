# Agentic search over a hierarchy of document clusters

## Introduction

Last quarter, our team hit a wall with semantic search on a 50-million-document corpus. Standard vector search—single-index, flat HNSW—was returning technically relevant results that were practically useless. A query for "Q3 billing discrepancies" would surface invoice PDFs, Slack threads, and Jira tickets all mixed together, forcing the downstream LLM to reason over a noisy context window. The precision@10 was abysmal.

We didn't need better embeddings. We needed a search strategy that understood *structure*.

Agentic search over a hierarchy of document clusters replaces the "retrieve-then-read" loop with a "navigate-then-read" loop. Instead of dumping top-k vectors into a prompt, an agent traverses a precomputed cluster tree, dynamically deciding which branches to expand, which to prune, and when to terminate. The result: 40% latency reduction and a 22-point jump in answer accuracy on our internal benchmarks.

This article breaks down the architecture, the trade-offs, and the production-grade implementation patterns we use.

## Why This Matters

Flat vector indexes optimize for *similarity*, not *utility*. In production RAG systems, this manifests as three concrete failures:

1.  **Context pollution**: Unrelated documents sharing semantic proximity (e.g., "billing" in marketing vs. finance) dilute the signal.
2.  **Token waste**: Feeding 20 chunks to an LLM when 3 would suffice burns budget and increases hallucination surface area.
3.  **Opacity**: When the answer is wrong, you can't debug *why* the retriever chose those vectors.

Hierarchical clustering imposes a taxonomy on the corpus. Agentic traversal turns that taxonomy into a decision process. The agent doesn't just fetch; it *investigates*. This maps directly to how senior engineers debug unfamiliar codebases: start at the module level, drill into suspicious directories, ignore the test fixtures.

If you're running RAG at scale—legal discovery, internal knowledge bases, customer support automation—this pattern moves retrieval from a cosmetic similarity filter to a first-class reasoning component.

## How It Works

The system has three layers: an **offline indexing pipeline** that builds the cluster hierarchy, an **online agent** that navigates it, and a **verification loop** that prevents runaway traversal.

### Offline: Building the Hierarchy

1.  **Embed** all documents with a frozen encoder (e.g., `bge-large-en-v1.5`).
2.  **Cluster** recursively using spherical k-means (cosine similarity) until leaf clusters hit a target size (we use 128 docs).
3.  **Summarize** each cluster with an LLM to generate a *cluster descriptor*—a dense natural language summary of the cluster's thematic coverage.
4.  **Persist** the tree: nodes store centroid vectors, child pointers, descriptors, and doc IDs at leaves.

### Online: Agentic Traversal

The agent receives a query and a root node. It maintains a **frontier** (priority queue of candidate nodes) and a **context buffer** (collected leaf documents).

At each step:
1.  **Score** frontier nodes against the query using centroid similarity.
2.  **Select** the top node. If it's a leaf, harvest its documents into the context buffer.
3.  **If internal**: expand it—push children onto the frontier with updated scores.
4.  **Decide**: continue, backtrack, or terminate based on a policy (budget, confidence, diversity).

### Termination Policies

We use a composite policy:
- **Hard budget**: Max 50 node expansions or 2000 tokens in context buffer.
- **Confidence threshold**: Stop if top frontier score < 0.35 (cosine) for 3 consecutive steps.
- **Diversity guard**: Penalize expanding siblings of already-visited clusters to avoid rabbit holes.

## Core Concepts

### Cluster Node
```python

    level: int                    # 0 = root

    descriptor: str               # LLM-generated summary
    doc_count: int                # Total descendants
```
Immutable, serialized via `msgpack` for fast mmap loading.

### Spherical K-Means
Standard k-means minimizes Euclidean distance. For normalized embeddings, cosine similarity == Euclidean distance on the unit hypersphere. We use `sklearn.cluster.MiniBatchKMeans` with `n_init=1` and custom initialization (k-means++ on a sample) for speed. Recursion stops when `doc_count <= LEAF_TARGET` or `level >= MAX_DEPTH` (we cap at 4).

### Cluster Descriptor
Not a keyword list. A 2-3 sentence natural language summary generated by a small instruct model (Llama-3.1-8B-Instruct) prompted with 20 sampled documents from the cluster. Example:
> "This cluster contains Q3 2024 invoices from the EMEA region. Key topics: VAT compliance adjustments, cross-border payment failures, and vendor onboarding discrepancies. Documents are primarily PDF invoices and internal audit memos."

Descriptors let the agent *reason* about cluster relevance without scanning every centroid.

## Examples & Code Walkthrough

Below is a production-hardened skeleton. It omits persistence/serialization but includes the traversal logic, scoring, and termination policies we run in production.

```python
import heapq
import numpy as np
from dataclasses import dataclass, field
from typing import Protocol, runtime_checkable
from collections.abc import Iterator

# ---------------------------------------------------------------------------
# Data Structures
# ---------------------------------------------------------------------------

@dataclass(frozen=True, slots=True)
class ClusterNode:
    node_id: str
    centroid: np.ndarray          # shape (dim,), unit norm
    level: int
    is_leaf: bool
    child_ids: tuple[str, ...]
    doc_ids: tuple[str, ...]
    descriptor: str
    doc_count: int

@dataclass(order=True, slots=True)
class FrontierEntry:
    score: float                  # Negative for max-heap behavior
    node_id: str = field(compare=False)
    depth: int = field(compare=False)
    parent_score: float = field(compare=False)

# ---------------------------------------------------------------------------
# Protocols for Dependency Inversion
# ---------------------------------------------------------------------------

@runtime_checkable
class VectorStore(Protocol):
    def get_node(self, node_id: str) -> ClusterNode: ...
    def get_documents(self, doc_ids: tuple[str, ...]) -> list[str]: ...

@runtime_checkable
class Embedder(Protocol):
    def embed_query(self, text: str) -> np.ndarray: ...  # Returns unit vector

@runtime_checkable
class TerminationPolicy(Protocol):
    def should_terminate(self, state: "TraversalState") -> bool: ...

# ---------------------------------------------------------------------------
# Traversal State & Policy
# ---------------------------------------------------------------------------

@dataclass(slots=True)
class TraversalState:
    query_vec: np.ndarray
    frontier: list[FrontierEntry] = field(default_factory=list)
    context_docs: list[str] = field(default_factory=list)
    visited_nodes: set[str] = field(default_factory=set)
    expansions: int = 0
    consecutive_low_scores: int = 0
    sibling_penalty: dict[str, float] = field(default_factory=dict)

class CompositePolicy:
    """Combines budget, confidence, and diversity guards."""
    def __init__(
        self,
        max_expansions: int = 50,
        max_context_tokens: int = 2000,
        min_score_threshold: float = 0.35,
        low_score_patience: int = 3,
    ):
        self.max_expansions = max_expansions
        self.max_context_tokens = max_context_tokens
        self.min_score_threshold = min_score_threshold
        self.low_score_patience = low_score_patience

    def should_terminate(self, state: TraversalState) -> bool:
        # Budget checks
        if state.expansions >= self.max_expansions:
            return True
        # Rough token estimate: 4 chars/token
        if sum(len(d) for d in state.context_docs) > self.max_context_tokens * 4:
            return True
        # Confidence check
        if state.frontier:
            best_score = -state.frontier[0].score
            if best_score < self.min_score_threshold:
                state.consecutive_low_scores += 1
                if state.consecutive_low_scores >= self.low_score_patience:
                    return True
            else:
                state.consecutive_low_scores = 0
        return False

# ---------------------------------------------------------------------------
# Scoring Functions
# ---------------------------------------------------------------------------

def cosine_score(query: np.ndarray, centroid: np.ndarray) -> float:
    """Both vectors assumed unit-normalized."""
    return float(np.dot(query, centroid))

def apply_sibling_penalty(
    score: float,
    node: ClusterNode,
    state: TraversalState,
    penalty_factor: float = 0.15
) -> float:
    """Discourage expanding multiple children of the same parent."""
    if node.level == 0:
        return score
    parent_id = node.node_id.rsplit("-", 1)[0]  # Assumes ID scheme "parent-child"
    penalty = state.sibling_penalty.get(parent_id, 0.0)
    return score - penalty

# ---------------------------------------------------------------------------
# Core Agent
# ---------------------------------------------------------------------------

class AgenticSearcher:
    def __init__(
        self,
        store: VectorStore,
        embedder: Embedder,
        policy: TerminationPolicy,
        root_id: str = "root",
    ):
        self.store = store
        self.embedder = embedder
        self.policy = policy
        self.root_id = root_id

    def search(self, query: str) -> list[str]:
        qvec = self.embedder.embed_query(query)
        state = TraversalState(query_vec=qvec)

        # Seed frontier with root
        root = self.store.get_node(self.root_id)
        initial_score = cosine_score(qvec, root.centroid)
        heapq.heappush(state.frontier, FrontierEntry(
            score=-initial_score,
            node_id=root.node_id,
            depth=0,
            parent_score=0.0,
        ))

        while state.frontier and not self.policy.should_terminate(state):
            entry = heapq.heappop(state.frontier)
            if entry.node_id in state.visited_nodes:
                continue
            state.visited_nodes.add(entry.node_id)

            node = self.store.get_node(entry.node_id)

            if node.is_leaf:
                # Harvest documents
                docs = self.store.get_documents(node.doc_ids)
                state.context_docs.extend(docs)
                # Update sibling penalty for parent
                if node.level > 0:
                    parent_id = node.node_id.rsplit("-", 1)[0]
                    state.sibling_penalty[parent_id] = state.sibling_penalty.get(parent_id, 0.0) + 0.1
            else:
                # Expand internal node
                state.expansions += 1
                for child_id in node.child_ids:
                    child = self.store.get_node(child_id)
                    raw_score = cosine_score(qvec, child.centroid)
                    adjusted = apply_sibling_penalty(raw_score, child, state)
                    heapq.heappush(state.frontier, FrontierEntry(
                        score=-adjusted,
                        node_id=child_id,
                        depth=entry.depth + 1,
                        parent_score=raw_score,
                    ))

        return state.context_docs
```

### Key Implementation Notes

1.  **Unit normalization is non-negotiable**. Centroids and query vectors *must* be L2-normalized. We enforce this at index build time and in the embedder protocol.
2.  **Sibling penalty** prevents the agent from exhausting budget on one branch. The penalty accumulates per parent (0.1 per expanded child). Tuned on a validation set.
3.  **Frontier deduplication** via `visited_nodes` handles DAG structures if clusters overlap (we don't overlap, but it's cheap insurance).
4.  **Token accounting** uses character length as a proxy. In production we plug in the actual tokenizer for the generator LLM.
5.  **Dependency inversion** (`VectorStore`, `Embedder` protocols) lets us swap backends (Redis, LanceDB, mmap files) and models without touching traversal logic.

## Best Practices

1.  **Calibrate leaf size to your generator's context window**. We target 128 docs/leaf because our generator (Llama-3-70B) has 8k context and we reserve 4k for prompt+answer. Each doc averages ~30 tokens after chunking. Math: `4000 / 30 ≈ 130`.
2.  **Precompute centroids as float16**. Saves 50% memory with negligible cosine distortion. Load as float32 for scoring.
3.  **Warm the frontier with descriptor scoring**. Before expanding a node, score its *descriptor* against the query using a cross-encoder. Only expand if descriptor score > threshold. Cuts useless expansions by ~30%.
4.  **Log every traversal decision**. Store `(query, node_id, score, action)` tuples. This is your debug dataset for policy tuning.
5.  **Version your cluster tree**. Rebuild weekly. Serve old tree during rebuild via blue/green. Never mutate in-place.

## Common Mistakes & Anti-Patterns

### 1. Flat Cluster List (The "Shallow Hierarchy" Trap)
**Mistake**: One-level clustering (e.g., 500 clusters, no hierarchy). Agent becomes a linear scan over cluster centroids.
**Fix**: Enforce minimum depth ≥ 3. The hierarchy *is* the search space compression mechanism.

```python
# Anti-pattern: flat clusters
def build_flat_index(docs, n_clusters=500):
    kmeans = MiniBatchKMeans(n_clusters=n_clusters)
    labels = kmeans.fit_predict(docs)
    # No recursion, no tree, no navigation
```

### 2. Ignoring Descriptor Quality
**Mistake**: Using centroid vectors only for scoring. Centroids drift; they represent *average* semantics, not *discriminative* semantics.
**Fix**: Invest in descriptor generation. Use few-shot prompting with negative examples. Evaluate descriptors with human annotators on a sample.

### 3. Runaway Agent (No Termination Discipline)
**Mistake**: While loop with only `max_expansions`. Agent gets stuck in a dense subtree of marginally relevant clusters.
**Fix**: Implement the composite policy above. Add a *diversity-aware* score: `score * (1 - visited_siblings / total_siblings)`.
