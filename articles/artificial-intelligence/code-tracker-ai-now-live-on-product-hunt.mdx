# 🚀 Code Tracker AI — Now Live on Product Hunt

## Introduction  
When we first tried to “chat” with a monorepo of 200k lines, the naive RAG approach fell apart. Chunking by line numbers split class definitions, and re‑embedding the whole repo on every push turned CI into a 30‑minute slog. The result was a product that could not answer “Where does `UserService` get instantiated?” without hallucinating unrelated test files.  

We needed a system that knew the *structure* of the code as well as the *meaning* of it. The outcome is **Code Tracker AI**, a dual‑brain architecture that serves both deterministic graph queries and probabilistic semantic search. It’s now live on Product Hunt and ready for engineers who need context that actually works.

## Why This Matters  
Every large codebase ships with a *symbol graph*—who calls whom, what implements what, which imports are real. Traditional vector stores ignore that graph, causing noisy, token‑hungry prompts. Code Tracker AI solves three production‑grade pain points:

1. **Accurate structural queries** – “Show me all callers of `checkout()` across the repo.”  
2. **Incremental updates** – Only re‑parse files that changed and their dependents, not the entire repo.  
3. **Budgeted context assembly** – Guarantees a hard token ceiling while preserving whole symbols, no mid‑function cuts.

If you ship code, you ship maintenance. This architecture cuts maintenance cost by giving you a *compiler‑aware* memory of your own source.

## How It Works  

```mermaid
flowchart TD
    A[Source Files] --> B[Tree-sitter WASM Parser]
    B --> C{UCO Builder}
    C --> D[Universal Code Object (UCO)]
    D --> E[Symbol Graph Store]
    D --> F[Embedding Service]
    E --> G[Graph Traversal Engine]
    F --> H[Vector Index (HNSWlib/Qdrant)]
    G --> I[Query Orchestrator]
    H --> I
    I --> J[Context Packer]
    J --> K[LLM Prompt]
    I --> L[Intent Classifier]
    L --> G
    L --> H
```

**Step‑by‑step flow**

1. **Parsing** – Tree‑sitter binaries run in a WASM sandbox. They emit an AST per file, language‑agnostic and zero‑dependency.  
2. **UCO Construction** – The AST is transformed into a *Universal Code Object* (UCO). The UCO captures a content‑addressable hash of the signature, a body hash for change detection, and location metadata.  
3. **Symbol Graph** – Edges (`CALLS`, `IMPORTS`, `INHERITS`, etc.) are stored as a compressed adjacency list in SQLite (local) and a PostgreSQL replica (team server).  
4. **Embedding Service** – For each UCO we generate a 768‑dim vector using a lightweight sentence‑BERT model. This feeds a HNSWlib index for low‑latency nearest‑neighbor search, with a fallback to Qdrant for distributed scaling.  
5. **Intent Classification** – A tiny RoBERTa model (`< 5 MB`) runs on the raw query and outputs `STRUCTURAL`, `EXPLANATORY`, or `DEBUGGING`.  
6. **Orchestration** – The query planner routes:  
   * `STRUCTURAL` → Graph Traversal (BFS/Dijkstra) using the symbol graph.  
   * `EXPLANATORY`/`DEBUGGING` → Vector Search + cross‑encoder reranker.  
7. **Context Packer** – A greedy knapsack algorithm respects a hard token budget while guaranteeing seed symbols (the file the user is viewing) and their dependencies are included.  
8. **Prompt Assembly** – The packer yields a list of source blocks; the orchestrator concatenates them into a single prompt and forwards to the LLM.

## Core Concepts  
- **UCO (Universal Code Object)** – The in‑memory representation that ties a symbol to its source, signature, and change‑detectable hash. It is *not* a database schema; it is the shape of our reasoning.  
- **Symbol Graph** – Stored as CSR (Compressed Sparse Row) in SQLite for sub‑millisecond traversals. Edges are typed to support precise query semantics.  
- **Budgeted Context Assembly** – Tokens are the currency. The packer’s score = `0.7 * GraphCentrality + 0.3 * SemanticSimilarity`. It never splits a function or class; it prefers whole units.  
- **Incremental Parsing** – When a file changes, we recompute its UCO, update the graph edges, and run a dependency‑propagation walk to find which other nodes reference the changed file. Only those nodes are re‑embedded.

### 1. UCO Definition (TypeScript)  
```ts
// src/uco.ts
export interface UCO {
  id: string; // SHA‑256 of signature + body
  kind: 'function' | 'class' | 'interface' | 'module' | 'call_edge';
  language: 'ts' | 'py' | 'go' | 'rs';
  signature: string; // normalized: "func(user: User, opts?: Options): Promise<Result>"
  bodyHash: string; // hash of the raw implementation (for delta detection)
  location: {
    file: string;
    start: { line: number; column: number };
    end: { line: number; column: number };
  };
}

/**
 * Builds a UCO from a Tree‑sitter node.
 * Throws if the language is unsupported; falls back to `null` on parse errors.
 */
export function buildUCO(node: TSNode, source: string, lang: string): UCO | null {
  if (!SUPPORTED_LANGUAGES.has(lang)) {
    console.warn(`Unsupported language ${lang} for node ${node.type}`);
    return null;
  }

  const sig = normalizeSignature(node, source);
  const body = extractBody(source, node);
  const bodyHash = crypto.createHash('sha256').update(body).digest('hex');
  const id = crypto.createHash('sha256')
    .update(sig + bodyHash)
    .digest('hex');

  return {
    id,
    kind: mapNodeType(node.type),
    language: lang as UCO['language'],
    signature: sig,
    bodyHash,
    location: {
      file: node.location?.file ?? '',
      start: { line: node.start.line, column: node.start.column },
      end: { line: node.end.line, column: node.end.column },
    },
  };
}
```

### 2. Packer Core Logic (Python)  
```python
# src/context/packer.py
from dataclasses import dataclass
from typing import List, Generator, Set

@dataclass
class ContextBlock:
    uco_id: str
    content: str      # Full source code of the symbol
    tokens: int       # Pre‑calculated via tiktoken
    score: float      # 0.7 * graph_centrality + 0.3 * semantic_sim
    deps: List[str]   # UCO IDs required for compilation (imports)

def pack_context(
    blocks: List[ContextBlock],
    budget: int,
    seed_ids: List[str],
) -> Generator[ContextBlock, None, None]:
    """
    Greedy knapsack that respects a hard token budget.
    Guarantees:
        - All seed blocks are emitted first.
        - Dependencies are emitted before dependents.
    """
    # Map for O(1) lookup
    block_by_id: dict[str, ContextBlock] = {b.uco_id: b for b in blocks}
    included: Set[str] = set()
    token_spent = 0

    # 1. Force‑include seeds (the file the user has open)
    seeds = [b for b in blocks if b.uco_id in seed_ids]
    seeds.sort(key=lambda b: -b.score)  # highest score first
    for block in seeds:
        if token_spent + block.tokens <= budget:
            yield block
            included.add(block.uco_id)
            token_spent += block.tokens

    # 2. Topological pass for dependencies
    # Build adjacency: block -> list of its deps
    dep_map: dict[str, List[str]] = {b.uco_id: b.deps for b in blocks}
    # Reverse mapping: dep -> list of blocks that depend on it
    reverse_dep: dict[str, List[str]] = {}
    for b in blocks:
        for dep in b.deps:
            reverse_dep.setdefault(dep, []).append(b.uco_id)

    # Queue of ready blocks (no un‑included deps)
    ready: List[ContextBlock] = []
    for block in blocks:
        if block.uco_id in included:
            continue
        if all(d in included for d in block.deps):
            ready.append(block)

    # 3. Greedy fill
    while ready:
        # Sort by score per token (higher efficiency first)
        ready.sort(key=lambda b: -(b.score / b.tokens))
        block = ready.pop(0)
        if token_spent + block.tokens <= budget:
            yield block
            included.add(block.uco_id)
            token_spent += block.tokens
            # New ready items whose deps just got satisfied
            for dependent in reverse_dep.get(block.uco_id, []):
                if dependent in included:
                    continue
                dep_block = block_by_id[dependent]
                if all(d in included for d in dep_block.deps):
                    ready.append(dep_block)
        else:
            # Cannot fit this block now; keep it for later if budget frees up
            ready.append(block)

    # 4. Optional: spill‑over loop (budget may have slack after topological pass)
    # Simple: re‑evaluate remaining ready blocks with fresh budget.
    if token_spent < budget and ready:
        ready.sort(key=lambda b: -(b.score / b.tokens))
        for block in ready:
            if token_spent + block.tokens <= budget:
                yield block
                token_spent += block.tokens
```

### 3. Symbol Graph Edge Ingestion (Rust)  
```rust
// src/graph.rs
use std::collections::HashMap;

#[derive(Debug, Clone)]
pub enum EdgeKind {
    Calls,
    Imports,
    Inherits,
    References,
    Tests,
}

#[derive(Debug)]
pub struct SymbolGraph {
    // adjacency list: node_id -> Vec<(node_id, EdgeKind)>
    adj: HashMap<String, Vec<(String, EdgeKind)>>,
}

impl SymbolGraph {
    /// Insert a directed edge. Returns `true` if the edge is new.
    pub fn add_edge(&mut self, src: &str, dst: &str, kind: EdgeKind) -> bool {
        let entry = self.adj.entry(src.to_string()).or_default();
        let pair = (dst.to_string(), kind);
        if !entry.contains(&pair) {
            entry.push(pair);
            true
        } else {
            false
        }
    }

    /// Breadth‑first traversal from `start` respecting edge weights.
    pub fn traverse(&self, start: &str, max_depth: usize) -> Vec<String> {
        let mut visited = Vec::new();
        let mut queue = std::collections::VecDeque::new();
        queue.push_back((start.to_string(), 0));
        while let Some((node, depth)) = queue.pop_front() {
            if depth > max_depth {
                continue;
            }
            visited.push(node.clone());
            if let Some(edges) = self.adj.get(&node) {
                for (nbr, _) in edges {
                    if !visited.contains(nbr) {
                        queue.push_back((nbr.clone(), depth + 1));
                    }
                }
            }
        }
        visited
    }
}
```

## Best Practices  
- **Token budgeting** – Never assume a 128k window is unlimited. Pre‑calculate token counts for every symbol (tiktoken for TS/JS, tokenizer for others) and enforce a hard cap before packing.  
- **Incremental pipelines** – Cache the AST per file. On change, run a *dependency diff* using the symbol graph to limit re‑embedding to the affected subgraph.  
- **Graceful degradation** – If Tree‑sitter fails on a file (syntax error, binary not found), fall back to a line‑based chunk and mark the UCO as `invalid`. The graph traversal will skip it, and the semantic layer can still surface the raw text for the LLM.  
- **Consistency across environments** – Store the UCO IDs as content‑addressable hashes. The same source yields the same ID regardless of CI or local dev, simplifying caching and CI reproducibility.  

## Common Mistakes & Anti-Patterns  

| Mistake | Why It Hurts | Fix |
|---------|--------------|-----|
| **Splitting symbols mid‑function** | Forces the LLM to reconstruct broken logic, inflating token usage and hallucination risk. | Use whole‑unit packing; pre‑compute token sizes per symbol and never cut a block. |
| **Re‑embedding the whole repo on every push** | Turns CI into a latency bottleneck and spikes embedding costs. | Track changed files via Git diff, propagate dependencies through the symbol graph, and only re‑embed the affected subgraph. |
| **Relying solely on vector similarity** | Vectors blur structural boundaries; `User` from `models` vs `@prisma/client` become indistinguishable. | Combine graph traversal for structural queries with vector search for explanatory tasks. |
| **Ignoring token budget in the orchestrator** | Prompts overflow model windows, causing truncation and poor answers. | Centralize budgeting in the packer; enforce a hard limit before any LLM call. |
| **Hard‑coding language‑specific parsers** | Adding a new language requires re‑writing the ingestion pipeline. | Use Tree‑sitter’s WASM distribution; language support is a matter of swapping the binary. |

## Performance Considerations  
- **Memory** – The CSR adjacency list for a 200k‑symbol repo occupies ~30 MB in SQLite (with `better-sqlite3`). The vector index (HNSWlib) adds another ~50 MB.  
- **CPU** – Building UCOs is O(N) where N is the number of AST nodes. In our benchmark, a monorepo of 500 files parses in ~1.2 s on a single core.  
- **I/O** – The packer runs in pure Python; each iteration performs a few hash‑lookups and integer comparisons, negligible compared to LLM inference.  
- **Scalability** – Horizontal sharding of the vector index (Qdrant) keeps latency under 30 ms for 10 M vectors. The graph store remains a single SQLite file (or a read‑replicated Postgres cluster) because traversals are cheap.

## Frequently Asked Questions (FAQ)  

**Q: Do we need a separate index for each language?**  
A: No. The UCO model is language‑agnostic; the only language‑specific piece is the parser binary. All symbols are stored in the same graph and vector index.

**Q: How do we handle monorepos with multiple roots?**  
A: The graph stores absolute file paths. The resolver normalizes imports using the same logic as the language’s module resolver, so `../lib` and `./src/../lib` map to the same node.

**Q: What happens when the LLM exceeds the token budget?**  
A: The orchestrator catches `ContextLengthExceeded` errors, reduces the seed set, and retries with a tighter packer configuration. The user sees a concise answer plus a “show more” link that re‑triggers a new request with a larger budget.
